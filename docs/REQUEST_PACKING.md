# 单次请求内完成更多规划：三组对照

2026-09-19，yuesheng 既有 5090 服务上的独立原型实验。验证“将当前信息足够的操作放进一次请求”的理念；本轮不使用分类旁路、不使用码表，也没有安装引擎内多阶段状态机或接入完整 Pi Agent。

## 三组

- `single_step`：外层只暴露 plan，但每次最多一步。这是人为限制的逐步对照，不能冒充最强原生基线。
- `native_multi`：原生暴露 read/write/replace/check，允许一次返回多个调用。
- `single_plan`：外层只暴露 plan，一次最多八个异构步骤，之后由同一个外部执行器顺序执行。

三组共享模型、任务、可用动作语义、源码观察、工作目录、temperature=0、4096 单次输出上限、每次尝试最多八次规划请求。每次尝试使用新的缓存 namespace，尝试内允许前缀复用。固定随机种子交错执行，两次独立重复；不排除首次请求，不挑成功样本。无单独的最终 LLM 总结调用，三组都以成功 check 加独立验收结束。

三类任务：新建小型 UTF-8 文件读写模块及测试；修复已给出源码的 total 函数并写测试；相同修复但初始仅给文件名，必须先读取未知源码。测试均要求至少三个 unittest 测试。独立 oracle 不提供给模型。

执行器仅允许任务列出的文件及 read/write/replace/check；check 固定运行 unittest，没有任意 shell 工具。路径越界、未观察的非空文件覆盖、错误替换均拒绝，步骤失败后停止本批后续步骤。读取未知源码时不能同时计划依赖它的修改；已观察源码的重复读取不构成新信息边界。Python 产物/测试仍是可执行代码，这个工具目录不等于 OS 沙箱。

## 正式复测

18/18 尝试全部通过；保存产物独立复验 18/18 通过，用量完整，无分类控制记录。下表每组均为相同的六个任务（三类 × 两次）：

| 指标 | 单步请求 | 原生多工具 | 单个 plan |
|---|---:|---:|---:|
| 合计秒数 | 47.943241 | 25.797355 | 22.409237 |
| 模型请求数 | 22 | 14 | 8 |
| 输入 token | 21,642 | 12,806 | 6,368 |
| 输出 token | 4,510 | 2,282 | 2,230 |
| 分类控制记录 | 0 | 0 | 0 |
| 通过 | 6/6 | 6/6 | 6/6 |

plan 相比原生多工具：本轮时间下降 **13.13%**，请求数下降 **42.86%**，输出 token 仅下降 **2.28%**。逻辑输入 token 下降约 50.27%，不等于实际未缓存 prefill 工作量下降同等比例。没有测量模型 forward 次数或分离 GPU 计算/调度/网络耗时，不能把请求数当作模型内部计算次数。

相对人为单步组，时间下降约 53.26%。主要比较应使用允许多工具的原生组，不能只引用这个更大的百分比。表示方式、schema 和输出轨迹仍有差异，不能把所有时间差精确归因于一次网络往返。

### 每次任务的两轮均值

| 任务 | 单步：秒 / 请求 | 原生多工具：秒 / 请求 | plan：秒 / 请求 |
|---|---:|---:|---:|
| 新建文件读写代码及测试 | 9.845 / 3 | 5.460 / 2 | 4.718 / 1 |
| 修改已观察源码及写测试 | 7.089 / 4 | 3.263 / 2 | 2.770 / 1 |
| 先读取未知源码，再修改与测试 | 7.038 / 4 | 4.177 / 3 | 3.716 / 2 |

新建任务的 plan 在一次请求中完成“写实现、写测试、运行检查”的规划；后续执行仍在模型外。未知源码任务用第一次请求读取，第二次完成后续计划，没有假装一次请求能获得尚未执行的读取结果。已知源码任务的 plan 仍包含一次冗余 read，说明并未消除所有工具操作，但不需要新增模型请求。

这支持“尽量一次规划已确定工作，遇到真正的新信息再返回”的有限实测方向。普通原生多工具也已经获得大部分批量收益；只把工具名字换成 plan 并不保证收益。三类小任务、两次重复不足以推出复杂工程或生产并发的通用加速。

## 首轮测试器问题

`request-packing-20260919-a` 的全部 18 次记录保留：单步 6/6、原生 6/6、plan 4/6。测试器将所有“read 与修改同批”都拒绝，包括已在上下文提供源码的任务；两个 plan 尝试在执行前被过严规则拒绝。

修复为仅在读取未知源码时要求返回，新增边界回归测试，并将三组全部在新目录重新运行。未覆盖或删除旧记录，也没有只重跑 plan 成功样本。源码与任务提示未因修复改变；执行器条件统一改变。正式结果来自 `request-packing-20260919-b`。
