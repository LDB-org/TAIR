# edit 修复后的最终内容学习

2026-09-20。原来的完成回调只观察当前成功 plan 内的 write。若最初 write 后检查失败，
该 plan 不入表；后续 edit 修好文件并检查成功，也因没有 write 而不入表。生成修复过的
最终内容因此无法用于后续内容复用。

完成回调现在观察成功 plan 中明确的 write 和 edit 目标，共用最终 UTF-8 内容读取、
工作区范围、普通文件、1 MiB 学习读取上限以及缺失/无法读取跳过规则。不扫描工作区，
不解析 bash 命令，不修改原工具执行行为。仅 edit 的新增条目记录为 new_edit_content；
write 的原有日志值保持兼容。重复路径和相同最终内容仍去重。

新增集成测试使用真实 Pi 0.85.1 的 write/edit/bash 工具及生产 executePlan：先 write
后失败，再用 edit 修改并执行成功检查；完成回调保存修正后的最终内容。另覆盖 read
不触发学习，以及 edit 目标最终缺失时不学习陈旧参数。使用固定 Pi 的完整 505 项测试
通过，归档 62401 个校验条目和 2853 个导入文件通过。

这仍是成功执行后的内容观察，不是语义验收，也没有把已有条目中的错误内容清除。
仅 edit 修改的文件会保存完整最终文本，而不只是替换片段；下次是否可以复用仍需结合
新任务与文件状态判断。纯 bash 写文件仍未自动学习。失败 plan 的已完成部分仍不入表。
本轮未运行 GPU 性能测试，没有证明额外学习可以带来稳定命中或端到端加速。
