# 动态码表扩大验证

2026-09-19，在 yuesheng 5090 现有模型服务上，比较实际 `compact_edit` 开启和关闭 `PIJIT_SAFE_CODEBOOK` 的表现。关闭组使用 `PIJIT_DISABLE_CODEBOOK=1`，两组都使用相同的结构化编辑生成路径。本次没有修改运行时、安装补丁或重启模型服务。

## 方法和范围

34 个有学习依赖的步骤 × 两组 × 四次独立重复，共 272 次调用。每次重复从空表开始，每次调用是新进程；每一步的两组顺序随机交错。包含首次生成与填表成本。计时包含进程启动、准备、模型请求、应用、内部行为检查和外部 AST/行为验收，不包含夹具恢复和检查脚本布置。

保留原 16 步，新增减半、不同参数的复合请求及重复、反向否定范围及重复、中文帮助、负数和零、仅注释变化、不同工作目录、验证命令变化与恢复、条件保护的语义改写及重复、无验证重复。34 步不等于 34 个独立代码项目：基础程序仍是 argparse CLI 和除零保护两类，主要扩大复用边界与重复次数。

验证命令变化用相同检查程序加不同命令注释实现，单独测试命令摘要的失效规则。它不证明系统能识别“命令不变但检查脚本内容变化”。不同路径场景同时改变工作目录，验证工作区隔离，不单独证明同一工作区中不同文件的隔离。

检查程序不提供给模型；行为检查验证目标行为，AST 比较拒绝未请求的修改。预期命中标签只用于报告，不参与运行时选择。所有尝试计入结果；失败不删除、不重试替换。

## 首轮验收脚本问题

`safe-codebook-expanded-20260919-a` 在完成 61 次调用后中止，其中两次负数测试误报失败：预期 AST 使用 `Constant(-2)`，而 Python 实际解析为 `UnaryOp(USub, Constant(2))`。两组都正确生成了 `default=-2` 并通过内部行为检查。原记录、未完成尝试及日志全部保留。

修正独立验收器，增加正负号回归检查后，正式实验在新目录 `safe-codebook-expanded-20260919-b` 从空表重跑。首轮不与正式实验混算，也不将验收器修正称为码表运行时修复。

全部 272 次正确完成，命中或拒绝行为与预期一致，没有发现错误复用。总耗时下降 **46.77%**；四次独立重复分别下降 **45.64%、48.00%、45.94%、47.40%**。暖任务耗时下降 **92.69%**，所有 68 次命中均为零模型请求、零输入 token、零生成 token、零分类控制记录，项目检查仍执行。

冷或拒绝复用的 68 个任务，两组请求数、输入量和生成量完全相同，耗时差仅约 0.4%，不作为码表收益。当前收益主要来自能确定匹配的任务完全省去推理，而非模型分类算子本身更快。

204 个真实生成请求全部匹配到服务端分类旁路事件。服务启动时间、镜像和健康状态前后一致。335 项单元测试和历史归档校验通过。派生数据在 `SAFE_CODEBOOK_EXPANDED_RESULTS.json`。

## 仍然存在的限制

- 验证命令改变后，原条目被正确拒绝，但生成后的相同编辑被现有去重逻辑挡住，不能更新验证来源。两次请求均继续生成；恢复原命令后恢复命中。共四次重复都观察到这一现象，是学习效率问题。本轮保留运行时不变，没有顺手修复。
- 通用请求的语义改写需要重新生成、验证、精确入表；同义表达不能直接复用旧条目。完整 CLI 类型绑定是另一条可泛化新参数的路径。
- 本轮预期暖任务占 50%，这是设计的受控序列，不是生产命中率。实际收益取决于任务重复、支持的类型绑定和验证开销。
- 仍是两类基础程序的编辑阶段实验，不是完整 Agent、真实大型仓库覆盖或任意自然语言的通用加速。命令摘要也不是检查内容或全项目环境的版本摘要。

## 复现

```sh
python benchmarks/benchmark_safe_codebook.py --suite expanded --repeats 4 \
  --url http://127.0.0.1:8000 --out results/experiments/NEW_SAFE_EXPANDED
```

正式报告由 `benchmarks/report_safe_codebook_expanded.py` 生成。原始记录包含每次源码、结果、用量、码表快照和最终持久化状态。多工作区步骤的通用 book-before/book-after 文件按目录枚举取首个码表，不能单独用于证明对应工作区的内容；该场景另核对响应中的检索条数、路径和最终对应工作区码表。
