# Plan 完成协议与恢复长尾修复

2026-09-20。承接条件回复 B/C 轮，本轮进行了 D/E/F/G 四轮、每轮六题三组，共 72 次真实 GPU 运行。四轮是逐步调试，不是独立重复评估；失败与超时均保留。

## 当前实现

- 实验提示要求 plan 明确给出完成或继续决定，但模型漏写时正常执行，记录 missing_completion_decision，不再拒绝整个 plan。尚未把该决定改为生成 schema 的必填字段。
- 条件回复允许附加 expected_outputs，以零基执行步骤索引绑定已知 bash 合并输出，包含换行逐字比较；截断、索引错误、重复索引、未知输出或不匹配均回到模型。读取/搜索始终回到模型。没有正则或子串匹配，也不抑制工具输出。
- PIJIT_RECOVERY_LATEST=1 只在最近一次工具结果失败时强制恢复分支，随后重新开放分类目录。历史错误保留；成功读取并不被当作已修复。默认仍保留旧路由，待扩大验证后再决定推广。
- 只有完成回复、没有执行步骤的合法非空结果，被规范化为普通 reply_user。它仍是一轮模型生成，不算省掉推理；空内容或没有可绑定步骤的输出条件不被当作成功。
- jsonschema 错误只向 Pi 返回紧凑的验证规则消息；实际实例、路径与错误原因保留在本地 metrics。避免完整 schema 中的 “500 lines” 被 Pi 识别成服务器 500 错误而自动重试。该错误消息修正完成于 G 轮之后，另以固定 Pi 的真实重试函数验证，不混称为 G 轮性能收益。

PIJIT_PLAN_SUCCESS_REPLY 与 PIJIT_RECOVERY_LATEST 均为实验开关，默认不启用。用户现有码表、服务部署与默认配置没有改变。

## 环境与口径

yuesheng 既有 6×RTX 5090、DeepSeek-V4-Flash-Vision-Exp、TP2/PP3、Pi 0.85.1。每轮任务为 jsonl_base、jsonl_changed、unique_base、totals_base、repair_failure、normalize_labels；同题三组随机交错。使用本地 tokenizer 和会话 prefix cache。两条 plan 独立空测试表、持续学习但关闭复用，排除动态码表收益。全部七种原生工具仍可用，未重启服务。

端到端时间含 Pi 启动、全部推理、工具、错误恢复和最终回复；外部 oracle 单独验收。每题 150 秒上限。E 轮超时后额外花 0.359 秒确认 running=waiting=0，再开始下一组，该屏障在任务计时之外单列。产物正确不代表 Agent 正常结束或遵循先检查的显式顺序。

## 哪些机制真的被使用

D/E/F/G 的预生成回复直接发送次数全部为 0；没有自然生成 expected_outputs 条目。精确回执机制目前只在受控真实 Pi 集成测试中证实工作，不能宣称它已经带来 GPU 任务提速。G 有三次完成回复规范化，均仍算模型请求。

恢复路由的变化有运行时 trace 证据：E 修复任务 79 次强制恢复，F/G 各一次。G 不再出现该任务的无限检查或结束解析错误；仍需更多任务和重复测试排除其他退化。

## 错误重试的独立复核

从 F 轮提取的 schema 错误文本长 29999 字符，原样送入固定 Pi 0.85.1 的 isRetryableAssistantError，返回 true；紧凑验证错误返回 false；真实 HTTP 500 仍返回 true。F 记录了三次自动重试。只修正本项目输出格式，没有改动 Pi 安装包或关闭所有重试。验证信息留在本地日志。

472 项测试通过，含真实 Pi 执行链上的成功、读取、失败、未知输出、精确回执匹配与不匹配路径，以及历史错误保留、新错误恢复、跨用户任务重置、完成回复规范化和旧版无 jsonschema 导入兼容性。

本轮主要收获是定位并修复恢复长尾、结束解析和误重试边界，不是证明新的通用加速机制已经成熟。下一步应扩大恢复路由测试，并重新设计必填完成决定的 wire schema；动态码表的适用性与错误复用问题仍未解决。
