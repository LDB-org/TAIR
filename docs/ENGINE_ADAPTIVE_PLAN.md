# 引擎分类与自动入表闭环

2026-09-19，新增 `deploy/adaptive_plan.py`，接入既有 `/v1/openjev/toolcall` 引擎接口。没有安装新补丁、修改 tokenizer 或重启服务；也没有改变默认 Pi Agent 路径。

## 已实现的数据流

1. 从调用方指定的磁盘 JSON 码表加载已验证的源码、契约及校验值。空表也是合法状态。
2. 根据本次用户任务、各输出模块的完整契约及码表构建分类候选：每条源码一个候选，另加 GENERATE。没有关键词或正则意图路由。
3. 一个推理请求进入现有 vLLM 分类接口：候选 logits 直接选条目或 GENERATE，使用原请求 KV 继续生成完整 plan 参数。外部只得到名为 `plan` 的调用。
4. 选中条目时生成目标路径等短参数，客户端展开原源码；同一 plan 的其他模块可以完整生成。若后续阶段发现分类误选，允许在同一响应内放弃复用，改为生成。
5. 外部执行器检查路径、编译及输出集合，在临时目录交给调用方提供的可信行为验证器。复用也必须通过当前需求的验证。
6. 整个 plan 验证通过才发布产物，并自动把新生成模块连同原始契约、SHA-256 和验证证据加入码表。验证失败不发布产物、不入表；下一次调用重新从磁盘读取。多个产物文件的发布不是跨文件事务，发布期间的文件系统错误可能留下部分产物。

码表写入使用文件锁、读取后合并、精确内容去重、临时文件 fsync 和原子替换。当前保留最近 15 条，给现有接口的第 16 个分类候选留作 GENERATE。数据落在客户端磁盘，载入 CPU 内存；源码进入模型上下文时会产生相应 KV，不是把整张码表长期放在显存中。

独立 tokenize 请求仅准备 token，不执行模型推理。候选准备并行，字母 token ID 有进程内缓存；这部分开销也计入总时间。每个 plan 是一次推理 HTTP 请求、一次分类控制决定、同一引擎会话的后续参数生成，不是一次模型 forward。

## 5090 验证

既有 DeepSeek-V4-Flash-Vision-Exp `/model` 服务，6 × RTX 5090，TP2/PP3，客户端推理并发 1。vLLM `0.28.1rc1.dev137+g5ab628dd1`，xgrammar `0.2.3`。镜像、挂载路径、tokenizer 校验值及服务启动时间记录在环境文件；未独立确定权重的上游 commit。

两轮独立空码表，每轮按相同十步序列执行：UTF-8 首次/换路径复用、UTF-16 首次/复用、文本复用并生成新的二进制模块、二进制复用、禁止覆盖首次/复用、自动建目录首次/复用。每一步随机交错朴素和引擎两组，合计 40 次。两组输出上限都是 2048，temperature=0，关闭 thinking，不排除首次请求，不重试失败样本。

朴素组使用同一个 plan 工具但始终生成完整源码，不提供码表；也做同样的外部验证和存档入表以覆盖执行成本，后续不会使用该表。引擎组自行累积、选择和复用条目，未人工预填种子。两组模型提示格式及生成轨迹不同，因此这不是单独隔离分类 kernel 贡献的消融实验。

正式 B 轮结果，每组均为相同的 20 次任务：

| 指标 | 朴素生成 | 引擎分类＋自动码表 |
|---|---:|---:|
| 全流程秒数 | 57.121 | 33.294 |
| 推理 HTTP 秒数 | 55.802 | 23.934 |
| 客户端准备秒数 | 0.000 | 8.100 |
| 生成 token | 5,808 | 1,320 |
| 分类控制记录 | 0 | 20 |
| 推理请求数 | 20 | 20 |
| 逻辑输入 token | 9,710 | 18,950 |
| 行为验收 | 20/20 | 20/20 |

全流程包括动态候选准备/tokenize、推理 HTTP、客户端展开、行为验证、产物发布及自动入表，不含建隧道、Pi 启动或最终 LLM 总结。引擎逻辑输入为 prefix 加实际选中的 continuation，分类控制记录单独统计；不是独立测量的实际 GPU prefill 工作量。

本轮整体省时 **41.71%**，生成 token 减少 **77.27%**；输入 token 增加。性能包含复用、提示差异、源码更简短等共同影响，不能全部归因于分类内核，也不能直接与前一轮固定单条码表的 10.78% 比较。

| 子集 | 每组次数 | 朴素秒数 | 引擎秒数 | 朴素 / 引擎生成 token |
|---|---:|---:|---:|---:|
| 新契约、需要生成 | 8 | 21.940 | 15.645 | 2,194 / 856 |
| 已入表的重复任务 | 10 | 27.968 | 13.103 | 2,864 / 206 |
| 复用＋生成混合 | 2 | 7.213 | 4.546 | 750 / 258 |

重复任务全部命中，省时 **53.15%**，生成 token 减少 **92.81%**。两轮分别由空表自动积累为 5 条，混合 plan 新生成的二进制模块也在下一步成功命中。共 12 个复用步骤；没有错误源码通过行为验收。

分类阶段本身不是全对：两次“自动建目录首次”都选中了不创建目录的 UTF-8 条目，后续阶段在同一个请求内放弃复用、生成新源码，通过检查后自动入表；未增加第二次推理。应将此记录为 **2/20 分类决定需要纠正**，不能把最终 20/20 成功写成分类准确率 100%。验证失败时当前实现报错且不入表，不会隐藏追加模型重试。

服务器事件逐请求复核了 20 次调用：分类行 `sampler_bypassed=true`，暂停/恢复时 KV block IDs 和 computed_tokens 相同，继续阶段启用参数 grammar。同一请求可能有 TP rank 的两条 classify 日志，不能将其计为两次分类决定。完整产物另行复验 40/40 通过。

## 首轮失败保留

`engine-adaptive-20260919-a` 全部 40 次记录保留，朴素 20/20，引擎 8/20。初版分类提示允许输出 GENERATE 单词，而候选实际为字母；客户端又拒绝“选中条目但后续全部生成”的纠正。12 次在产物发布和入表前失败，异常路径没有完整保存原始响应/token 用量，A 的计数不完整，不能计算公平加速比。

B 明确回退字母、允许同一响应纠正、在客户端解释前保存原始引擎响应，同时并行 tokenize 并缓存字母 ID。两组全部重新从空码表开始，未覆盖 A，也未选择性重跑成功样本。A 的原始源码快照、失败原因、日志和校验清单均保留。

## 接口与边界

```python
from adaptive_plan import PlanBook, infer, execute_and_learn

book = PlanBook(state_dir / 'plan-codebook.json')
contracts = {'text_io.py': '完整、准确的模块行为要求'}
result = infer(url, user_task, contracts, book)
admitted_ids = execute_and_learn(result, contracts, output_dir, book, verifier)
# verifier(path, contract) 必须来自可信调用方：通过返回证据字符串，失败抛异常。
```

运行环境需可导入 `deploy/adaptive_plan.py` 并安装 jsonschema，服务必须已有对应版本的 fused 分类接口。当前仅创建新的 Python 输出文件，每次最多四个模块；不会覆盖已有文件。每个 plan 只分类选择一个码表条目，同一条目可绑定到适用路径，其他模块生成；尚未实现引擎内任意多次条目选择的状态机。

调用方必须提供各模块契约和可信验证器。本轮验证器有明确的文件 I/O 行为检查，未把 LLM 自己写的测试当成正确性证明。对任意自然语言任务，契约提取、通用可靠验收、大码表检索及复杂修改仍未解决。成功结果说明这个受限闭环已接通，不是通用 Agent 质量保证。验证子进程也不是 OS 沙箱。
