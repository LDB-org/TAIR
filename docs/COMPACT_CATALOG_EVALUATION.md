# 紧凑候选目录：端到端实验

2026-09-20。目标是减少分类前读取的候选内容以及动态目录对历史前缀缓存的影响。新增可选 `PIJIT_COMPACT_CATALOG=1`：候选上限从 7 降到 2，仍由原 BM25 检索排序；动态目录从 system prompt 移到历史后的独立 user 消息，明确标记为参考数据。所有原生子工具、完整生成回退、每子工具 2048 token 预算保留。候选内容不截断；该开关可能减少召回率，必须以实际产物和恢复成本验收。

沿用会话 cache salt 和本地 tokenizer。服务端、模型权重及用户默认配置未改。本轮没有重启服务，没有清空用户码表，使用用户码表只读快照在隔离状态中学习。

## 方法

同一 yuesheng 服务（6×RTX 5090，TP2/PP3，DeepSeek-V4-Flash-Vision-Exp），Pi 0.85.1。21 项自编回归任务，native tools 与 TAIR 两组各一次，串行随机交错，正常终止及独立产物 oracle 联合验收。端到端包括启动、工具、错误恢复、最终回答，所有失败计入。此实验不是公开外部基准，也不是多次重复的统计结论。源码、输入、运行顺序在推理前冻结。

`compact-catalog-paired-20260920-a` 因 PATH 指向其他 Pi 安装，TAIR 启动时报 ENOENT，未发出模型请求；确认后中断并保留原始记录。该不完整环境失败轮不纳入模型性能比较。中断时测试器未等待子进程退出就写校验清单，两份日志仍被子进程追加；原清单原字节保存在 `PREMATURE_CHECKSUMS.txt`，差异及原因记录于 `interruption.json`，子进程退出后才生成最终校验清单，日志正文未编辑。修正为显式 Pi 0.85.1 PATH 后，在全新目录 `compact-catalog-paired-20260920-b` 重跑。

## 结果

两组均 21/21 通过，42 份产物再次独立验收一致。但 TAIR 270.32 秒，对照 213.85 秒，耗时增加 26.4%。TAIR 生成 17985 token，对照 20398；TAIR 67 次请求、15 次工具错误，对照 83 次请求、4 次工具错误。TAIR 逻辑输入 306311 token，对照 228513。不能因生成 token 少就称为加速。

TAIR 25/67 次请求报告非零前缀缓存，共复用 59136 token。重复任务子集 TAIR 44.97 秒，对照 34.52 秒，均 4/4 通过。`nullable_changed` 本轮通过，但不代表历史误复用问题已经普遍解决。

结论：本组合不启用为默认。目录后置与 top-2 同时改变，尚未单独消融，不能严格归因于其中一个。轨迹中观察到旧内容不适配和额外修复，与变慢相伴。完整数据见 [JSON](COMPACT_CATALOG_EVALUATION.json)、[冻结原始记录](../results/experiments/compact-catalog-paired-20260920-b/)。
