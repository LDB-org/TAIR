# 结构操作协议：压缩提示与有类型参数

2026-09-18。此前可读目录版输出减少 53.35%，但总 tokens 增加 88.55%，未达到加速门槛。
本次目标是降低输入说明与失败回退成本，保留真实原生对照和所有失败记录。

## 两个明确分开的版本

`deploy/compact_structural_protocol.py` 新增两个 opt-in 协议，旧协议不变：

1. compact：以源码派生的语义名代替行列 ID，去掉重复 ID/名称映射；关键字按目标限定。普通参数仍用 Python 表达式字符串。
2. typed：普通参数使用 JSON 数字、布尔值、字符串或分隔符数组，由引擎转成 Python 字面量；仅条件和提前返回结果保留表达式生成。异常类型为有限集合，消息为普通字符串。提示中不再重复完整目标目录，模型从源码及命名规则选择目标，grammar 仍限定合法集合。

函数使用函数名，调用优先使用简单的首个字符串参数（如 `--host`），否则使用被调用函数名（如 `json.dumps`），赋值语句使用变量名（如 `sock`）。冲突用源位置后缀消歧。
所有映射绑定源文件版本，表达式/操作验证、重叠检查与最终 compile 检查仍在。

关键字约束来自已有关键字，以及本地标准库 `print`、`json.dumps` 的签名；typed 还从已有字面量/签名默认值推导值类型，另声明 separators 的双字符串数组类型。
这不是完整 Python 类型推导或名称绑定分析。源代码重绑定名字、自定义调用的新参数、复杂动态对象等尚未覆盖，不能声称此登记表准确描述所有运行时 API。
不支持的操作需拒绝/回退，不能凭关键字约束推断修改语义必然正确。

## 对照方法

- 两组均移除重复任务说明和源码行号，避免靠更冗长的原生基线制造收益。
- 相同模型、源码、任务、生成参数；每个请求新 cache salt，先后顺序交替，任务顺序固定 seed 打乱。
- 真实 Pi edit 对照；结构方案失败后最多一次真实原生回退，从 pristine 重新开始。
- 总 tokens 包括失败与回退。完整耗时包括请求、应用修改、隔离任务测试和原有 17 项 unittest。
- 共享 yuesheng 负载未隔离，分别报告排队、生成时间与完整耗时，不将排队波动当作协议收益。
- 执行在 bubblewrap 私有网络，只用 loopback。新增测试先在原文件上失败，模型不见测试源码。
- 每个版本开始后冻结；版本间保留独立目录、源代码快照与所有请求。

compact：8 类任务各两次，证据 `results/experiments/pi-compact-structural-20260918-a/`。
typed：沿用上述 8 类任务，另增加 JSON 拒绝 NaN 与端口边界前置检查；这是两类新的同项目任务，不是跨项目生产验证。
compact 暴露的表达式值错误用于 typed 设计，不能把沿用的八类任务称为独立验证集。

16 对均最终通过；原生首轮 16/16，compact 首轮仅 6/16，10 次需要原生回退。
输出 3137→2753（减少 12.24%），总 tokens 34145→57509（增加 68.43%）；

主要问题是表达式字符串误填、选错操作与漏改；缩短说明没有修复协议理解。

## typed 冻结设置

typed 在上述结果后冻结，使用相同八类回归任务，加两类新任务，各一次，共 10 对。
两组都将唯一的一次任务描述置于源码之后，源码和任务信息相同。结构组额外使用操作说明和少量消歧目标名。
证据 `results/experiments/pi-typed-structural-20260918-a/`。
这不是把 compact 的失败样本删掉重算，两个版本分别统计。

## typed 第一轮结果

10 对最终均通过；原生首轮 10/10，typed 首轮 8/10，两次原生回退。
输出 2036→704（减少 65.42%），总 tokens 21272→24015（增加 12.89%）。
引擎记录的生成时间 23.09→13.54 秒（减少 41.36%），排队 20.64→63.09 秒；
完整耗时 68.63→105.19 秒。不能把生成阶段收益说成已经稳定端到端加速。

失败分别为紧凑 JSON 任务选错 print 目标并尝试同位置多次插入；socket 创建异常把赋值语句当作 return_if 的条件表达式。
八个无回退样本输入各比对应原生多 23 tokens，大目录输入问题已显著缓解，但不能只保留这些成功样本报告总收益。

## 带任务范围筛选的 typed（scoped）

进一步增加基于源码和任务文本的确定性候选检索：先匹配明确提及的函数，再匹配调用名/模块名/字符串参数，
保留匹配调用及其所属语句和函数；无检索证据时保留全部候选。不是按测试答案指定正确操作。
生成 grammar 和运行时都限制同一候选集合。增加一个与测试源码无关的 catch 示例，区分条件判断与异常捕获。
这同时改变了候选范围和提示，不能将结果归因于其中一个单独因素。

源码词法匹配可能误筛目标，不是语义证明。最终模型仍需选择操作及参数，功能测试失败仍回退。
本轮使用同样十类任务各一次，属于调试回归而非新的独立验证集。
证据：`results/experiments/pi-scoped-typed-20260918-a/`；参数：`--typed-protocol --scoped-protocol --repeats 1`。

包含两次失败及原生回退，输出减少 **76.90%**，引擎报告生成时间减少 **52.91%**；
总 tokens 仅减少 **0.35%**，完整耗时增加 **18.60%**。预设端到端加速筛查不通过。
按任务类别聚类 bootstrap 的耗时降幅描述性 95% 区间为 -126.21%～43.66%，跨零。
这批是经过调试的十个同项目任务，不是独立泛化证明。

两次回退：

- 紧凑 JSON 已选对 json.dumps，但给出了 `["", ": "]` 分隔符，造成不符合预期的输出。
- 拒绝 NaN 任务选择在 main 入口判断尚未初始化的局部变量，功能测试报 UnboundLocalError。

别名、空输入、socket 创建异常、workers 默认值、timeout 上限、空 host、Unicode 输出、端口边界检查均首轮通过。
没有为了获得正向输出降幅丢弃失败成本，也没有将失败样本改成手写正确答案。

## 剩余性能边界

此轮每请求 mean_itl_ms 的中位数：原生基线 11.39 ms，结构首轮 30.97 ms。
说明输出减少比例不能直接当作生成时间下降比例。不同输出内容、长度、共享批次和解码路径均可能影响这一差异，
尚未用同输出、受控负载试验隔离原因，不能断言全部来自 grammar。
扣除引擎报告排队后的剩余墙钟为 49.89→39.42 秒；这仍包含传输、入队前处理、修改与测试，不是纯 GPU 推理时间。

当前可以准确报告：“在这批调试任务上，包含回退后的输出减少 76.9%，引擎报告的生成阶段耗时减少 52.9%。”
不能扩写成“Agent 稳定加速 52.9%”或生产可用。
进一步收益取决于减少语义错误/回退，以及隔离验证每 token 解码开销和共享排队，而不是继续只缩短字段名。
