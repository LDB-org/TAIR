# 同一次请求内选择复用或生成

2026-09-19，yuesheng 六张 RTX 5090，既有 DeepSeek-V4-Flash-Vision-Exp `/model` 服务，TP2/PP3，客户端并发 1。vLLM `0.28.1rc1.dev137+g5ab628dd1`，xgrammar `0.2.3`；未修改或重启服务。模型挂载路径、镜像、tokenizer 校验值及启动时间保存在实验环境记录中，未独立确定模型权重的上游 commit。

本轮实现并验证独立 API 原型：只暴露一个 `plan` 工具，LLM 在同一个响应中输出 `reuse` 或 `write`，也可以混合两者。执行器再展开引用并写入文件。没有额外“先分类、再生成”的请求，也没有正则意图匹配。

## 码表和对照

码表包含上一轮实际生成且通过独立行为检查的 UTF-8 文件读写模块，来源 `file-io-20260919-a/hybrid/project-after/file_io.py`。保存为磁盘 JSON 后重新加载，包含原始源码、适用契约、来源和 SHA-256。唯一参数绑定是目标路径；不能通过复用参数改变编码、覆盖语义或父目录行为。为排除评测中学习造成的污染，本轮全程固定码表，尚未实现本原型内的新条目自动准入。

八类任务各重复两次，三组随机交错，共 48 次：相同契约、中文改写、修改目标路径、UTF-16、自动创建父目录、仅新建禁止覆盖、二进制文件、文本复用与二进制生成的混合任务。

- 朴素生成：没有码表，只能输出完整源代码。
- 带码表生成：得到相同码表与源码，但仍只能输出完整源代码。
- 自适应 plan：得到相同码表，允许引用条目或生成新代码。

三组均仅一次请求，temperature=0，输出上限 4096，关闭 thinking，每次使用新的 cache_salt，不重试、不删除失败样本、不额外请求最终总结。全量码表源代码也放进了上下文；本轮不是大规模码表检索实验。

## 结果

每组为相同的 16 次任务；全部通过独立行为检查，所有用量完整。时间包含 HTTP 推理、客户端验证、文件写入及独立验收，不含隧道、码表准备或 Pi 启动。仅 HTTP 时间另存于 JSON，不能把这些秒数当成纯 GPU 计算时间。

| 指标 | 朴素生成 | 带码表生成 | 自适应 plan |
|---|---:|---:|---:|
| 合计秒数 | 40.172 | 44.042 | 35.841 |
| HTTP 推理秒数 | 38.414 | 42.401 | 34.306 |
| 请求数 | 16 | 16 | 16 |
| 输入 token | 9,522 | 15,634 | 16,738 |
| 输出 token | 3,856 | 4,322 | 3,228 |
| 分类控制记录 | 0 | 0 | 0 |
| 通过 | 16/16 | 16/16 | 16/16 |

自适应方案相对朴素生成：时间下降 **10.78%**，输出 token 下降 **16.29%**；相对同码表完整生成，时间下降 **18.62%**。输入 token 明显增加。三组请求数相同，本轮收益不是减少请求次数；主要观察到的是省掉部分重复代码输出，源码风格和上下文也影响结果。

| 任务组（每组尝试数） | 朴素秒数 | 带码表生成秒数 | 自适应秒数 | 自适应相对朴素 |
|---|---:|---:|---:|---:|
| 纯复用适用（6） | 13.917 | 15.371 | 9.222 | 省时 33.74% |
| 必须生成（8） | 21.320 | 20.524 | 20.605 | 省时 3.35% |
| 混合 plan（2） | 4.935 | 8.147 | 6.014 | 多耗时 21.88% |

6 次纯复用全部选择正确条目；8 次新约束任务全部生成；2 次混合任务各复用一份文本模块并生成一份二进制模块。同一 plan 中共 8 个正确复用步骤、10 个生成步骤，没有观察到错误复用。纯复用输出 token 从 1,324 降至 676。

未命中组与同码表生成组时间接近（自适应多 0.40%），没有增加第二次模型请求。但这不代表未命中零成本：相对朴素，输入上下文增加，具体案例也可能输出更长。例如仅新建任务的生成明显变长。混合任务中，朴素输出两份简短源码仅 476 token，自适应需要 586 token，因此虽然功能正确，却比朴素更慢；相对带码表完整生成的 854 token 才有优势。应保留这个负结果。

## 正确性和实现边界

执行器验证 schema、目标路径集合、重复路径、目录逃逸、条目 ID/hash 和源码编译，全部通过后才落盘。独立行为验收覆盖 UTF-8/UTF-16、Unicode、覆盖/追加、缺失文件、父目录、禁止覆盖保留原文件、包含非法 UTF-8 的二进制字节。验收未提供给模型，不负责选择分支或修复结果。存档产物另行完整复验 48/48 通过。

这些结构校验不能证明语义适用性；本轮 LLM 选对了，不等于所有任务都能可靠命中。只有一个条目和八类小任务、两次确定性重复，未测大码表混淆、复杂代码修改、并发、错误恢复或生产任务分布。Python 行为验收在本地子进程执行，并非 OS 沙箱。

本轮是普通 LLM 生成工具参数，在同一次响应内选择 `reuse/write`，不是新增引擎分类 kernel，也未接入完整 Pi Agent。外部执行器在响应后展开引用；引擎没有执行内部工具或消费执行结果。新生成代码自动验证、准入码表、跨任务学习的完整闭环仍需单独实现与验证。
