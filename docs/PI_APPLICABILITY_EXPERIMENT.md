# 操作适用性约束实验（2026-09-18）

结论：新增约束能拒绝特定非法表达式，但本轮没有降低实际原生回退比例，不能作为性能改进上线。
新协议 7 项中仅 1 项直接完成，6 项主动转原生；旧协议 5 项直接完成、2 项失败后转原生。
把主动转原生从失败计数中删除，会掩盖实际成本上升。

## 实现范围

`deploy/applicable_structural_protocol.py` 是独立实验模块，未替换默认生产协议。

- 根据源码过滤无法插入 guard、无法包裹 catch 的位置，禁止模块顶层 catch 后 return。
- 入口条件、返回值使用受限表达式 grammar：参数名、字面量、比较、有限布尔组合和小容器。
  不允许尚未初始化的局部变量，也排除调用、属性访问、推导式和算术表达式。
- JSON separators 限于保留逗号和冒号的四种组合。
- 解码后再次检查 grammar、源码版本和完整结束标记，再由既有引擎构造补丁并检查编译。
- 提供 `["native"]` 路由标记；当前实现随后发起独立的原生请求，不是同一次请求内完成原生编辑。

这是保守能力子集，并非完整 Python 数据流分析或类型系统。参数可能不支持所选比较，合法操作也可能不符合用户意图。
这些约束不保证业务正确、任意代码安全或文件写入的并发原子性。选择操作仍是 grammar 约束的自回归生成，未新增分类头，也未进行协议训练。

## 失败与诊断

旧协议紧凑 JSON 生成 `["", ":"]` 分隔符，行为测试失败；新 grammar 已排除此值。
旧协议修改除数在同一函数入口生成三个 guard，触发 `Overlapping edits`，随后原生成功。

新协议只有空任务返回直接完成，其余六项全部选择 `["native"]`。
其中修改除数确实超出能力，其余五项均有合法实现。这不是六次错误补丁，但同样产生六次额外请求。
`capability-probes/results.json` 保存六项手写协议的解码及行为检查，全部通过，证明候选能力存在。
这些是单独的能力诊断，不是模型成绩，没有向模型提供这些答案。

结果支持“模型过度选择原生路径”的观察；尚未隔离是提示、分支 token 概率、约束交互还是协议熟悉程度造成。
不能据此断言单靠微调必然解决。

下一步应保留已验证的硬约束，单独测试路由策略和操作选择：
候选操作及有效参数更明确地展示给模型，在独立数据上训练/校准支持与不支持的选择，
并探索同一次请求承载原生编辑以减少二次 prefill。
不能简单禁止原生回退，强迫不支持的任务生成错误操作。
验收同时看首次完成率、全部原生转交比例、最终正确率和包含失败的总成本。
