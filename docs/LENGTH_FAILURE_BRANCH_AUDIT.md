# Generation long-tail branch audit

The two timed-out ordinary TAIR cases in `first-tool-reuse-ablation-20260921-a` each recorded 17,408 generated tokens on the first failed HTTP request. Their original client did not retain the decision or finish reason. These records alone do not establish what the model generated or why it failed.

`benchmarks/audit_length_failure_branches.py` reconstructs native/general continuation token lengths with the frozen bridge and pinned tokenizer. Two calibration contexts produce identical suffix token IDs; the known lengths also match the recorded input-length multiset. The selected input length uniquely matches general (wire index 10) for `unique_base`, and write (wire index 2) for `unique_repeat`. Neither matches the remaining candidate lengths. See `LENGTH_FAILURE_BRANCH_AUDIT.json`. These are indirect branch inferences, not recovered original decisions.

A read-only scan of the existing server audit log matched the two worker request IDs and retained their metadata in `LENGTH_FAILURE_SERVER_AUDIT.json`; large KV block lists are omitted. Each has six classify events, one worker-slot retirement and one resume. There are zero classify events after resume for either ID. Resume prompt lengths (4,340 and 4,339) agree with the client records, and both resume with structured output and a 17,408-token limit. This evidence does not support classification continuing throughout the generation tail. Event multiplicity must not be counted as separate client requests.

The local server source now logs one `decision` event before queuing generation, with API request ID, selected index, control ID, candidate count, continuation length and budget. A failed generation logs that same ID, selected index, finish reason, generated count, exception class and JSON structural diagnostics. No prompt, schema, generated source or exception message is logged by these new events. Worker IDs may append a suffix to the API ID. This closes the evidence gap even if a client loses the response. The endpoint test checks correlation, accounting and absence of generated source.

This is diagnostic groundwork, not a measured acceleration or a fix for the generation tail. No server patch was installed, no model was restarted, and no user codebook was modified. The next live reproduction needs the new diagnostics to distinguish incomplete JSON from complete JSON followed by excessive whitespace or other output; the historical records cannot answer that question.
