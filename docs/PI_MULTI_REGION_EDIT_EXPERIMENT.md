# 多区域引用编辑实验

2026-09-18。已实现一次调用内选择 1～8 个不重叠区域并生成各自的 replacement。
实测可显著减少局部编辑的输出，但正确率及失败重试成本尚未解决，不能作为生产可用或稳定加速的证据。

## 实现与边界

`deploy/region_edit_protocol.py` 接受紧凑数组 `[["L136","replacement"],["L142","replacement"]]`。
引擎 regex 限定候选区域 ID、数组数量及字符串结构；内容由模型生成，没有新增分类头。
运行时校验原始文件 SHA256、输出完整性、区域内容、重复和重叠，按原始位置逆序应用，
最后检查 Python AST。全部检查完成才返回结果，失败不返回部分补丁。
基础缩进由运行时恢复。版本检查针对传入快照，并非文件系统并发写入的原子 CAS。
结构、语法合法仍不能保证修改满足任务要求。

实验为实际模型单次编辑操作及隔离运行测试，不是完整自主 Pi Agent 回合。
原生对照使用 Pi 0.85.1 的实际 edit 实现；模型为 yuesheng 的 DeepSeek-V4-Flash-Vision-Exp，
vLLM `0.28.1rc1.dev137+g5ab628dd1`，6×RTX 5090，TP2×PP3。
原有服务配置未变，temperature=0、thinking 关闭、max_tokens=4096。
每个任务从相同文件开始，新增检查先在原文件上失败；通过要求新增检查及原有 17 项 unittest 全部成功。
执行使用 bubblewrap 私有网络，仅 loopback。请求、响应、usage、文件和源码快照均保留。

## 全部实验记录

目录前缀为 `results/experiments/pi-multi-region-20260918-`。

| 目录 | 处理 | 首轮结果 |
|---|---|---|
| a | 单区域与数组混合协议；模型仍复制整函数，提前停止 | 调试记录，不汇入比较 |
| b | 数组协议，3 类任务各 2 次，双方交替顺序 | 原生 6/6，多区域 4/6 |
| repair | b 的两个失败样本，保留错误反馈与重试成本 | 各一次重试成功，最终 6/6 |
| c | grammar 限制首字符缩进，并解释单行与整块边界 | 多区域 5/6 |
| c-repair | c 的一个失败样本，最多两次反馈重试 | 两次均失败，最终仍 5/6 |

c 沿用 b 的原生对照，任务和文件相同，时间窗口不同。三个任务参与了协议调试，
不能当作独立 held-out 正确率。a 的未完成请求保留，不当作零成本成功样本。
c 完成后，本地 grammar 又补充禁止首字符为 JSON 控制字符；该补充仅通过单测，
没有冒充已运行的 c 版本。各目录 sources 和 request.json 保存实际版本。

## 输出与总成本

| 六个任务尝试 | 通过 | 输入 tokens | 输出 tokens | 输入+输出 |
|---|---:|---:|---:|---:|
| b 原生 | 6/6 | 14526 | 1304 | 15830 |
| b 多区域首轮 | 4/6 | 14052 | 424 | 14476 |
| b 多区域含全部修复 | 6/6 | 19248 | 670 | 19918 |
| c 多区域首轮 | 5/6 | 14322 | 380 | 14702 |
| c 多区域含全部修复 | 5/6 | 19691 | 564 | 20255 |

b 达到同样 6/6 验收时，输出减少 **48.62%**，但总 tokens 增加 **25.82%**。
不能把失败首轮的较少输出当作等质量收益，也不能隐藏重试输入。

成功的具体局部任务：

| 任务 | 原生输出，每次 | b 多区域输出，两次 | c 多区域输出，两次 |
|---|---:|---:|---:|
| 两处 CLI 默认值 | 165 | 22 / 22 | 22 / 22 |
| timeout 与 workers 边界 | 211 | 82 / 44 | 91 / 91 |
| ASCII 端口校验 | 276 | 127 / 127，均失败 | 42 失败 / 112 成功 |

默认值任务输出减少 **86.67%**。旧单区域协议在 ASCII 任务输出 464 tokens；
b 加上一次成功重试后每次输出 250 tokens，但每次总成本 5228，高于原生 2735。
c 的一次成功修改只输出 112 tokens，却采用较难读的条件表达式与 generator.throw；
通过功能测试也不等于可维护性更好。

## 失败原因与速度解释

b 的两个失败来自生成原始基础缩进，运行时拒绝。c 首轮失败合法输出三个替换，
却只重复 `int(..., 10)`，没有实现 ASCII 校验；后续反馈生成了不合法的 Python。
因此 grammar 防护生效与模型语义正确是两个不同验收项。

c 首个请求墙钟约 51.36 秒，其中引擎报告排队约 48.25 秒、生成约 1.62 秒。
服务器有共享负载，各轮请求时间不能直接用于宣称算法加速；本轮没有得出可靠加速比例。
