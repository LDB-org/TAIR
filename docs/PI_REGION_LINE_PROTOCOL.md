# 显式层级的多行编辑协议

2026-09-18。针对上一轮 6 次首轮失败，原始补丁存在两类问题：

1. 首行无缩进，后续行却携带原文件的绝对缩进；运行时再统一加基础缩进后，层级失配。
2. 把单行区域当成完整多行调用替换，留下原调用尾部；socket 包装补丁还复制了后面的 `try:`。

只做 `dedent` 不能消除第二类问题，也无法无歧义推断第一类补丁原本希望表达的语义。
本次新增独立协议，旧协议保持兼容，未对旧实验记录进行自动修补。

## 协议

```json
[["L62",[[0,"try:"],[1,"sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)"],[0,"except OSError:"],[1,"return False"]]]]
```

- 只允许完整 AST statement 区域，包含装饰器；不提供多行调用的开头、续行或复合语句头部作为独立候选。
- 每条替换包含至多 256 个 `[相对层级, 单行代码]`，层级 0～16，首行层级为 0；至多 8 个不重叠区域。
- 单行代码不带基础缩进、tab 或物理换行。生成 grammar 限定结构、候选与这些转义形式，运行时再次检查。
- 运行时从原文件的 INDENT token 推导统一缩进单位，支持统一空格缩进及 tab；混合单位明确拒绝，不猜测。
- 最终缩进 = 区域原基础缩进 + 相对层级 × 缩进单位。回退层级由显式整数决定，不扫描冒号猜测语法。
- 字符串里的转义 `\\n` 与空格原样保留。跨物理行字符串暂不支持，明确拒绝，避免添加基础缩进改变字符串值。
- 仍校验版本、目录内容、输出结束原因、区域重叠与最终 AST；所有检查通过才返回完整修改结果。

这能确定性解决空格渲染与区域边界，不能保证模型选择的层级、区域或修改意图正确。
没有新增分类头；层级和区域依然是 grammar 约束下的生成选择。并发文件原子提交仍不属于本模块能力。

## 验证方法

本地新增单测覆盖：2/4 空格与 tab、嵌套和回退层级、整条多行调用、装饰器、字符串空格/转义值、
错误层级和数据类型、物理控制字符、Unicode 转义绕过、重叠/过期/截断、删除与混合缩进拒绝。

真实模型对照保持原有方法：原生 Pi edit 一次，对照新协议失败后最多一次原生回退；
包括失败、回退、隔离测试的全部 token 与时间成本。
六类旧任务为回归集；新增线程池上限与创建 socket 前校验 timeout 两类任务为新需求。
每类两次，共 16 对。协议在开跑前冻结，不根据结果调整。
旧任务参与了问题诊断，不能把整个集合称为独立 held-out 泛化集。

运行命令：

```sh
python benchmarks/evaluate_region_holdout.py \
  --out results/experiments/pi-region-lines-NEW --line-protocol
```

证据：`results/experiments/pi-region-lines-20260918-a/`。每轮目录 create-only，保留实际源码快照和请求模板。

## 实测结果与限制

| 指标 | 原生 | 显式层级协议＋回退 |
|---|---:|---:|
| 首轮成功 | 16/16 | 10/16 |
| 最终成功 | 16/16 | 16/16 |
| 模型请求数 | 16 | 22 |
| 输出 tokens | 3216 | 4392 |
| 输入＋输出 tokens | 41384 | 59522 |
| 完整任务累计耗时 | 180.39 s | 360.71 s |
| P95 | 22.83 s | 44.24 s |
| 引擎累计排队 | 97.94 s | 248.02 s |
| 引擎累计生成 | 38.10 s | 53.06 s |

六类旧任务首轮仍为 **6/12**，两类新任务 **4/4**。不能用整体 10/16 声称旧任务正确率提升。
六次失败分类：

- 两次空输入任务选择重写整个函数，包含被协议禁止的物理多行 docstring；其生成层级也存在错误。运行时拒绝。
- 两次 socket 创建异常任务把 except 正文标成了错误层级，最终 AST 检查拒绝。
- 两次别名任务语法正确，但只增加了四个别名中的一个，功能测试失败。

输出增加 **36.57%**，总 tokens 增加 **43.83%**。墙钟约为原生两倍，但共享排队差异很大，
不能把整个时间差归因于协议。结构字段与完整语句重写增加了输出，且六次回退仍有成本。
这不是速度优化成功的证据。

已完成的是明确层级的确定性渲染、完整语句边界与拒绝不合法补丁；
尚未解决的是模型正确选择层级、区域以及完成全部需求。旧接口保留，新接口通过 `--line-protocol` 显式启用，
未替换生产服务默认路径。后续若要提高模型成功率，需要协议训练或进一步限定编辑操作，另设新任务验证。

84 项 pytest、原 results/raw 哈希校验及 69 项 published claims 校验通过。
