# 条件收尾回复实验

2026-09-20。目标：在同一次 plan 生成中准备最终回复，执行成功后直接发送，减少独立收尾推理。当前为 `PIJIT_PLAN_SUCCESS_REPLY=1` 实验开关，默认关闭；没有修改服务部署、用户配置或用户既有码表。

## 实现

分类分支和原生七工具保持不变，生成的 `rest` / `steps` 可追加一个 `on_success_reply` 项。bridge 校验它只能出现一次且在末尾，将其移出执行步骤保存为元数据；Pi 只执行实际工具。回复最多 600 字符，占既有八项计划中的一项，其生成 token 计入最初请求。实际发送不再请求推理，因此不重复记 token。

所有步骤成功、会话与原始上下文一致、对应工具结果成功且没有插入新用户消息或取消，才允许发送。read/grep/find/ls 不适用；bash 有任何新输出或截断信息则交回模型，不能只看退出码判断无需继续。write/edit 成功回执可直接通过。失败走原有恢复链。模型仍须判断计划是否覆盖全部需求；这些执行检查不能证明任务已完整或行为正确。

采用现有预算协议，无须服务端改动。A 轮最初使用额外顶层字段，触发服务端严格的预算形状检查和 HTTP 500；中断并完整保留证据，不纳入性能结果。B/C 已改为末尾回复项。

## 方法

yuesheng 既有 6×RTX 5090，DeepSeek-V4-Flash-Vision-Exp，TP2/PP3；Pi 0.85.1。与前轮相同的本地 tokenizer、会话 prefix cache 和每子工具 2048 / 总计 17408 预算。选择六个既有开发回归任务：jsonl_base、jsonl_changed、unique_base、totals_base、repair_failure、normalize_labels。包含 Python、JavaScript、新文件、约束变更和错误修复。

每轮三组、每题每组一次，顺序随机交错，共 18 次。三组是原生多工具、关闭复用的通用 plan、同一 plan 加条件回复。两条 plan 均从独立空测试表开始，持续学习但不提供复用候选，避免混有码表收益。计时包含启动、模型请求、工具、错误恢复和最终回复；独立产物验收不计时。两轮共 36 次正式运行，无超时，usage 完整，保存产物独立复验一致。不是外部 held-out benchmark，也不是稳定生产加速证明。

B 轮只在系统规则说明新功能，模型六题均未采用。C 轮进一步在分类后的生成指令加入明确用法与示例；仍保持独立执行检查。它是基于 B 反馈的开发迭代，不与 B 合并宣称统计显著性。

## 结果

| 轮次 / 方案 | 产物与正常结束 | 加上明确流程约束 | 完整耗时 | 请求数 | 生成 token |
| --- | ---: | ---: | ---: | ---: | ---: |
| B 朴素 | 6/6 | 6/6 | 53.87 秒 | 23 | 5145 |
| B 普通 plan | 6/6 | 6/6 | 53.11 秒 | 14 | 3226 |
| B 条件回复 plan | 6/6 | 6/6 | 55.21 秒 | 15 | 3633 |
| C 朴素 | 6/6 | 6/6 | 60.65 秒 | 25 | 5922 |
| C 普通 plan | 6/6 | 6/6 | 47.84 秒 | 14 | 3174 |
| C 条件回复 plan | 6/6 | **5/6** | 48.22 秒 | 13 | 3311 |

C 条件回复组 `repair_failure` 第一项是 read，而任务明确要求先运行 `python3 check_calc.py`。最终文件正确、检查文件没有修改，仍不满足明确的执行顺序约束。派生汇总现单列此项，而不只报告产物 oracle；原始冻结记录不修改。

B 轮预生成回复 0 次。C 轮预生成回复 1 次，发生在 unique_base；bash 返回数组和布尔检查信息，执行器判定需要模型解读而拒绝直接发送。两轮实际省掉收尾请求均为 **0 次**。C 组少一次总请求来自修复轨迹差异，不可归因于条件回复；该轨迹还违反了先检查要求。

C 条件回复组相对同轮普通 plan 用时多约 0.8%，生成 token 多约 4.3%。本轮没有证明新增机制带来净加速，不能把相对朴素的既有 plan 收益算到它头上。

## 验证与下一步

464 项测试通过（PATH 含固定 Pi 0.85.1），包括真实 Pi 加受控 bridge 回包的集成测试：成功写入仅一次 chat，并直接发送预生成回复；读取、命令失败、有输出的命令均需要第二次 chat。该集成测试证明执行链与拦截逻辑可用，不是 GPU 模型自然采用或性能收益证据。预算协议、一次性消费、新用户消息、会话改变、取消、输出截断亦有覆盖。归档校验通过，58827 条原始校验记录保持一致。实验结束服务 health=200，running=waiting=0；未重启服务。

当前瓶颈已具体化：模型很少主动选择合并收尾；即使选择，打印检查结果的命令还需下一轮解释。应继续研究如何在一次请求中表达明确的“完成/继续”决定和可核验的执行条件，而不是放宽成功判定或屏蔽输出。现有六题两轮不足以证明需要 SFT，也不足以证明更强提示已解决问题。动态码表的可靠性问题仍独立存在。
