# 完整 Agent 接入、码表扩展与失败恢复

后续存储更新见 [SQLite 码表与检索规模测量](PLAN_BOOK_STORAGE.md)：已取消默认 256 条截断。本文以下保留原实验时的实现和测量口径。

本轮把独立引擎原型接入了真实 Pi 0.85.1 循环，保留原有默认路径，新增显式启用的新建 Python 模块模式。外层模型生成任务和模块契约，`plan` 工具调用现有引擎分类接口，外部验证、发布并学习源码；随后 Agent 继续检查和最终回复。没有安装服务补丁或重启 vLLM。

## 完成的工程改动

- 通过 `PIJIT_ADAPTIVE_PLAN=1` 和 `PIJIT_NATIVE_PLANNER=1` 启用。首轮 API 强制选择 `plan`，参数仍由 LLM 生成；后续恢复普通工具选择。此模式适用于明确的新建 Python 模块任务，并非对任意用户请求自动判断后启用。
- 接入调用方配置的可信验证器。命令 argv 由环境配置，模型只能提供任务和契约，不能通过 plan 参数指定验证命令。复用和生成都先验证整个 plan，再发布产物和入表；已有文件不会覆盖。安全的工作区内绝对路径会归一化，越界或重复别名拒绝。
- 磁盘存储由 15 条扩为 256 条。词面检索选出最多 15 条候选供 LLM 分类，另保留 GENERATE。检索不等于命中判定，也不能保证任意改写都能召回；未召回时仍可生成。
- 验证拒绝复用后，记录该条目与当前契约的拒绝关系，并最多追加一次强制生成。第二次验证失败即停止；所有调用、token、耗时计入账单。拒绝某契约不会全局删除仍适用于其他需求的源码。
- 码表采用锁内合并、去重和原子替换，避免并发入表丢更新。交互状态和 `/jit` 分开显示 compact-edit 与 plan 的命中计数。
- 增加 `PIJIT_PLAN_DISABLE_REUSE=1` 对照：相同首轮 plan 策略、验证与入表，但不复用，用于隔离码表贡献。

使用方式见 [pijit README](../integrations/pijit/README.md)。模块契约并不自动成为可信事实，验证器必须检查原始需求和项目约束，不能仅检查模型自述的契约或模型自己编写的测试。

## 测试口径

yuesheng 既有 6 × RTX 5090，DeepSeek-V4-Flash-Vision-Exp `/model`，TP2/PP3，共享服务，完整 Agent 对照为客户端 C1。模型挂载制品的上游权重 commit 未独立确定。服务镜像、版本和 tokenizer 校验记录随审计结果保留。

三个固定版本项目的依赖适配任务：

- Rich `7f580bdcf07a3b269a0e786b6a3aa9c804f393cf`：解析 markup；新增约束改为原样保留标签。
- CPython `de54cf5be371a6f5e2e9f208c38def5f81d3ef02`：用原版 PurePosixPath 提取、排序去重 basename；新增约束改为保序且保留重复。
- TAIR 基于本轮开始时的 `466599e`：调用原版源码摘要函数；新增约束由 AST 规范化摘要改为原始文本摘要。

这是依赖真实源码的小型适配任务，不是三套完整上游测试或复杂仓库维护任务。每个项目跑冷启动、恢复相同工作区后的重复任务、新增约束，共九次任务；原生、plan 禁用复用、plan 启用复用三组交错，共 27 次。每组独立空码表起步，同组跨轮保留状态。初始只给出需求，没有预填答案源码。

正式 D 轮原生允许多个工具调用，各组外层均配置工作区级前缀缓存 namespace。允许缓存不等于已测量缓存命中率；不把逻辑输入 token 当作实际 GPU prefill 计算量。外层每次输出上限均为 4096；两种 plan 路径内层均为 2048。

端到端时间包括真实 Pi 启动和循环、全部外层/内层推理、文件操作、项目检查、最终回复及单列的最终验收；不包括夹具和 SSH 隧道准备。可信行为验证器在最后再次运行，上游文件另做哈希完整性检查；它不是未见过的隐藏测试集。

## 正式 D 轮结果

27/27 任务通过，全部用量完整，原生多工具开关及每次任务稳定的缓存 namespace 已从原始请求复核。三个重复任务的最终产物与首次入表源码逐字一致；新增约束均生成新实现，没有错误复用通过验收。

| 相同九次完整任务 | 原生多工具 | plan 禁用复用 | plan 启用复用 |
|---|---:|---:|---:|
| 端到端合计秒数 | 118.327 | 98.911 | 92.961 |
| 全部生成 token | 10,671 | 7,164 | 6,541 |
| 分类控制记录 | 0 | 9 | 9 |
| 外层推理请求 | 58 | 40 | 37 |
| 内层推理请求 | 0 | 9 | 9 |
| 总推理请求 | 58 | 49 | 46 |
| 复用命中 | 0 | 0 | 3 |
| 通过 | 9/9 | 9/9 | 9/9 |

启用复用组相对原生省时 **21.44%**，生成 token 减少约 **38.70%**；相对同样先走 plan 的禁用复用组，本轮整体省时 **6.01%**。主要收益来自外层工作流：即使禁用复用，plan 路径也已减少大量外层请求。

三个重复任务子集，启用复用相对禁用复用省时 **4.53%**。冷任务中两组也出现约 7.78% 的时间差，而它们没有可复用条目，说明外层轨迹和运行波动不可忽略。不能把整体 6.01% 当作精确、稳定的码表净收益。比如 Rich 新约束任务，原生 8.77 秒，启用复用的 plan 9.79 秒，仍存在更慢的任务。模块很短，避免生成的内容有限；没有证明所有完整 Agent 任务都会受益。

18 个内层调用均在服务事件中对应到分类行跳过普通采样和同一请求 KV 保留；两路并发及拒绝恢复实验的另外 11 个内层调用也逐一核验。C1、C2 分开计时，不混用单请求延迟与吞吐。完整 Agent 的外层仍有多次请求，没有宣称整个任务只有一次模型请求。

数值与分项目、分冷/热阶段数据见 `PLAN_AGENT_RESULTS.json`。A/B/C 的派生结果另存 `PLAN_AGENT_PILOTS.json`，不合并成正式性能结果。

## 稳健性验证

`PLAN_RESILIENCE_RESULTS.json` 和 `plan-resilience-20260919-a` 保留了九项真实 GPU 检查，全部通过：

- 256 条码表含 5 条此前生成并重新验证的真实条目，以及 251 条经常量返回检查的合成干扰项。五个目标均进入 15 条候选、分类复用成功。不能将这称为 256 条真实任务的学习评测。
- 注入“契约宣称支持建目录，但源码不支持”的坏条目。分类选择了该条目，行为验证拒绝，第二次纯生成正确恢复，原坏条目在该契约下被屏蔽；两次请求全计入。
- 另做一次确定性的验证器失败注入，确认恢复也只追加一次请求，且恢复请求不提供码表候选。
- 两个并发请求向同一空码表生成 UTF-16 和二进制模块，均通过验证，最终两条记录都存在；并发墙钟约 2.02 秒。这里只证明受控 C2 下的调用和入表正确性，不是生产吞吐、SLA 或长时间压测结论。

单元测试另覆盖容量淘汰、并发合并、损坏条目、契约级拒绝、连续两次失败停止、无产物/无入表、路径归一化、越界和重复别名，以及首轮强制 plan 不影响后续工具选择。

## 保留的中间结果

A、B 各 18 次任务功能通过，但仅注册工具或补提示词时，模型仍全部选择普通 write，plan 调用为零。这两轮不能归因于码表加速。C 用 API 明确选择首轮 plan，27 次通过、三个重复任务全部命中，但原生对照采用串行工具配置，因此最终性能结论使用更强对照 D。所有轮次均保留，没有只挑选成功任务重跑。

包含上游源码片段的完整 Agent 原始日志和校验清单保留在本地 `results/experiments/plan-agent-20260919-{a,b,c,d}/`，按仓库约定不提交外部评测快照；公开提交复现实验脚本、固定版本信息、派生汇总和审计。稳健性测试仅含自己的生成代码和合成干扰项，其完整证据提交到仓库。

仍有明确边界：需要可信项目验证器；仅新建 Python 文件，每个 plan 最多四个模块、一次条目分类；尚未验证复杂已有代码修改、多语言、超大语义检索或生产并发。多文件发布不是跨文件事务，文件系统异常可能留下部分产物。本轮改善了受控试用能力，不代表通用生产成熟。

最终 384 项仓库测试通过，本地存档 49,913 条 SHA-256 记录及 2,853 份导入实验文件校验通过。服务启动时间、镜像、tokenizer 和健康检查未变，所有临时 SSH 隧道已关闭。最终将 jsonschema 改为仅在 plan 推理时导入，另用无 site-packages 子进程验证旧 bridge 路径仍能导入；性能数字保留 D 轮原始源码快照的测量值，没有对这项启动开销优化追加提速推算。
