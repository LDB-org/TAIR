# 通用 Pi 工具 plan

2026-09-20，`--plan-only` 默认改为通用工具容器，不再把 plan 限定为 Python 模块
生成，也不再要求固定任务验证器。旧研究接口须显式使用 `--verified-modules`。

## 调用与执行

```text
Pi 对话上下文 + 原生工具 schema + 检索到的内容条目
  → 既有 /v1/openjev/toolcall
  → 引擎分类：起始工具 / 可复用内容 / 回复
  → 同一引擎请求保留 KV，生成余下 plan 参数
  → Pi 收到唯一的 plan({steps:[{name,arguments}, ...]})
  → 本地原生工具按序执行，结果进入下一轮上下文
```

外部只有 plan；内部支持 Pi 0.85.1 的 read、write、edit、bash、grep、find、ls。
执行器调用 Pi 原生实现，schema 取自实际工具，支持新文件、已有文件、不同语言、
命令执行及搜索。没有另一次外层 LLM 调用先生成 task/contracts。
全部推理请求的接口工具名均为 plan；最终回复分支映射为普通文字，不执行工具。

现有内核每次仍只有**一次分类决策**。起始工具或复用条目由分类选择，其余步骤的
名称和参数仍生成；这不是逐步反复分类的引擎内状态机。一次最多八步，输出预算仍
为 2,048 token。工具结果依赖无法凭空消失：读取未知内容后，需要下一轮才能据此
修改；已确定的修改与检查可以合并。最终总结也可能消耗一轮推理。

分类目录作为系统参考数据放在对话前，避免把码表里的历史任务当成新待办。
连续重复且已经成功执行的完全相同 write/edit 计划会被拒绝；中间发生其他操作、
上次失败或出现新的用户请求时不按该规则拦截。读取、命令轮询不按此规则禁止。

## 通用内容码表

成功完整执行的 plan 把 write 内容入库到独立的 `tool-plan-codebook.sqlite3`，
以用户任务作为检索描述，保留内容哈希；不要求它是 Python。SQLite 存储无默认
256 条截断，FTS 检索最多七个内容候选，给七个原生工具和一个回复分支留出空间。

分类选择内容条目后，继续生成可使用 `reuse_write(path)`，客户端展开成原生 write，
无需重新生成内容 token。选错后仍允许在同一响应中改为生成。原生 write、read、
bash 检查都实际执行，不缓存或伪造检查结果。成功复用才增加执行侧复用计数。

证据明确标为 `tool_execution_succeeded; semantic_correctness_unverified`，**不是可信
验收通过**。不再以固定验证器限制任务范围，也不把成功写文件等同于满足需求。
未命中时照常生成，不保证每次重复任务都命中。复用单位目前是完整 write 文本，
不是任意脚本参数化或缓存整段命令的执行结果。

执行错误立即停止剩余步骤，错误中保留已完成步骤结果，失败计划不入表；已发生的
文件副作用不自动回滚。取消信号传递给原生工具。入库失败与执行失败分开报告，
不会因为码表失败谎称之前的工具没执行。

只有外层 plan 发出 Pi 工具事件，内部步骤使用原生实现但不是独立外层事件。
第三方按工具拦截的权限扩展尚未验证兼容性；当前启动器本来就使用独立扩展配置。
这不是操作系统沙箱，当前 provider 的图片输入/工具图片输出传输也未实现。

## 实际验证

本地 Pi 0.85.1、隔离 Python 3.11，SSH 连接 yuesheng 既有 5090 服务，客户端 C1。
没有修改服务补丁或重启引擎。每例启动新 Pi 会话，同一临时工作区及内容库，
没有 `PIJIT_PLAN_VERIFY_ARGV`。计时包含启动、隧道、全部模型请求及工具执行。

正式 E 轮：[原始记录](../results/experiments/generic-plan-20260920-e/report.json)。

| 任务 | 实际内部操作 | 总耗时 | 推理请求 | 生成 token | 分类控制 |
|---|---|---:|---:|---:|---:|
| 创建 JavaScript | write → bash | 6.745 s | 2 | 100 | 2 |
| 相同 JavaScript 写到新路径 | 码表展开 write → bash | 6.657 s | 2 | 79 | 2 |
| 修改已有 JSON | read；下一轮 edit → bash | 9.377 s | 3 | 167 | 3 |
| 目录、文件、文本搜索 | ls → find → grep | 6.993 s | 2 | 181 | 2 |

四项功能断言全部通过。JavaScript 文件逐字节比对，JSON 独立解析检查 workers=7
且其他字段未变；确认没有额外文件。第二例实际发生内容复用。所有外层工具调用为
plan，HTTP 推理全部走 fused 接口，响应均为 same_engine_session；无额外原生
chat/completions 规划请求。搜索三种工具实际执行。模型检查之外另有独立结果断言。

这不是统计上充分的提速实验：短内容的启动/准备开销占比大，C 轮热任务甚至略慢。
所有试验保留：A 轮重复执行后被人工终止；B 轮分类选中内容但继续生成，复用断言
失败；C 三项通过；D 轮直接选 write，复用断言失败。E 将功能正确性和命中率分开
报告，并补充缓存优先提示与搜索案例，不删除或隐瞒之前的未命中。

411 项仓库测试通过。单元测试覆盖一般文本入库、分类分支展开、无固定验证器/无
外层规划请求、复用去重、取消/错误时跳过后续步骤及重复修改保护。

## 启动

```sh
PIJIT_SSH_HOST=rs-yuesheng-gpu-public \
PIJIT_PYTHON=/absolute/isolated/python \
node /absolute/TAIR/integrations/pijit/launch.mjs --plan-only
```

使用已验证的 Pi 0.85.1。更新后需退出旧进程重新启动，旧会话不会热加载实现。
用户本机 `~/测试/启动TAIR.command` 已切换为此模式，原 scanner.py 未修改。
