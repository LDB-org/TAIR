# 连续重复任务的码表净收益与失败

2026-09-21。本轮没有证明稳定的整体净加速：开启复用组 9/10 正确，90.51 秒；相同
plan 禁用复用组 10/10 正确，85.27 秒。不能因为重复子集更快就忽略需求变化时的错误。

## 方法

Pi 0.85.1，DeepSeek-V4-Flash-Vision-Exp，yuesheng 6×RTX 5090，TP2/PP3。
Python JSONL、JavaScript 去重两个任务家族，每家族首次一次、相同重复任务连续三次、
需求变化一次。三组交错串行，共 30 次完整 Agent 运行。每次新建 Pi 进程并重置工作区
文件，组内独立码表持续保留；重复提示、初始文件和 oracle 完全一致，只改变归档 ID。
不是读取上一次已经生成的文件，也不是跨组共享码表。

两组 plan 均开启 write references、recovery admission、本地 tokenizer、session prefix
cache，从空表学习。唯一实验开关差异是是否允许内容复用；禁用复用组也持续入表。
其他实验选项关闭，朴素启用原生多工具。总输出限 17408，plan 每子工具参数限 2048。
每任务 150 秒上限，无测试器重试。源码与任务在推理前冻结；没有人工插入预制正确条目。

## 已确认的错误来源

1. JavaScript 首次任务 bash 引号错误，模型恢复时创建 test_unique.mjs。常规学习把这份
   辅助测试脚本也挂在“实现 uniqueStrings”的整个任务描述下。第二次重复选中它作为
   实现写入，导入已不存在的 unique_base.mjs 报错。后续恢复生成正确实现，最终验收通过。
   这是内容条目语义与文件用途混淆，不是缓存内容损坏。
2. unique_changed 要求忽略大小写，模型沿用旧的大小写敏感实现，检查没有发现，正常
   结束但独立验收失败。引用内容重新单独执行 oracle 仍失败，确认是错误复用。
3. jsonl_changed 没有复用旧代码，但新生成代码试图在 json.loads 已经生成 dict 后检查
   重复键，此时重复信息已丢失。自检失败，读取、edit 和重测后修复，耗时 22.64 秒；
   禁用复用组 10.17 秒。该次不能标为误复用，亦不能由单轨迹证明候选导致生成错误。

汇总附七次引用内容的独立 oracle 审计：五次正确、一次错用辅助测试脚本但恢复成功、
一次需求变化误复用且未恢复。审计只在临时副本覆盖初次实际引用的内容，不修改冻结
记录；运行时无法访问这些独立 oracle。五次成功引用分别使用普通 write 短引用与旧
reuse_content 分类分支，不把两者混称为新增分类内核。

## 后续方向与边界

复用开关保持实验状态。下一步应先让入表记录区分具体文件与整个任务，防止辅助产物
