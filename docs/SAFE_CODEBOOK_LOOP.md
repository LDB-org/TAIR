# 生成、验证、入表与持久化复用闭环

2026-09-19，将保守复用接入已有 Pi `compact_edit` 运行时，新增 `PIJIT_SAFE_CODEBOOK=1`。默认不开启新模式，不修改模型服务。复用现有码表、文件锁、原子写入、源码绑定、回滚和项目检查，没有再造一套静态候选目录。

## 实现

1. 空表或没有可证明匹配的条目：调用现有引擎，分类结构化操作类型并生成参数。
2. 校验当前源码版本、解码和编译；明确的完整 CLI 请求还需生成操作与本地类型绑定完全一致。
3. 执行文件修改及配置的项目检查，失败回滚且不入表。
4. 成功后把生成操作、源码、路径、请求匹配信息及验证来源存入持久化码表。
5. 后续只有一个可证明适用的条目时直接复用，模型调用为零，但源码检查、应用与当前项目检查照常执行。

两种复用：完整 CLI 参数请求可为已学习操作绑定新参数；其他操作要求配置项目检查，且只允许原任务、原源码、原路径、相同验证命令来源下精确复用。不完整解析的否定或复合要求不能降级成“选最接近的单个动作”。条目有歧义、源码发生实质变化、验证来源变化时回退生成。

同时去掉旧 `pick_cached` 的“高分即可接受”路径。现在所有缓存选择都必须有完整显式绑定，或严格的原任务和源码匹配；分数不再充当语义正确性的证据。实际检索在进入模型选择前也过滤无依据的条目。

旧的未验证泛化条目不会自动成为新模式的可信条目。泛化无法绑定且没有项目检查时，仍可正常生成和执行，但不入表。项目检查的质量由调用者负责；测试命令通过不等于已经证明任意自然语言要求，模式名称也不是绝对正确性保证。

## 实验

两组唯一差别为码表开关；都走实际 compact_edit 结构化生成路径。基线不是另一个原生 vLLM 完整 Agent。每次调用启动新的 Python 进程，状态按组/重复隔离并保存在磁盘；两次独立重复，每次从空表开始。学习依赖顺序固定，组别在每一步随机交错。

16 步涵盖首次生成、精确重复、新默认值、已修改源码上再改值、新帮助字符串、新别名、复合请求首次和重复、否定范围、新条件保护首次和重复、不同条件要求、源码版本变更、无验证禁止入表。多数步骤恢复声明的源版本；updated_snapshot 特意使用前一步实际输出，验证顺序修改复用。

配置的行为检查检验 CLI 默认值、显式覆盖、帮助和别名，或除零条件与普通除法。独立 AST 检查保护所有未请求的源码变化。检查代码没有传给模型。最后的无验证任务只在外部验收，其 safe_book 结果不入表。

总时间包括进程启动、准备、模型调用、文件应用、内部项目检查及外部验收；不包括夹具恢复、检查文件布置。包含所有首次填表成本，没有预置答案或把冷轮隐藏。总耗时观察下降 **43.67%**；暖任务下降 **93.28%**，暖命中单次中位约 **98 毫秒**。

14 次命中中，10 次为明确绑定，4 次为验证过的原任务精确复用。所有命中从先前调用写入的文件读取，重启进程后仍可使用。暖命中输入 token、生成 token、分类控制记录均为零。这里的暖复用是确定性匹配，不是一次更快的模型分类。

18 次冷请求或被拒绝复用的请求，两组模型调用量及生成量相同；时间差属于运行波动。不能把该部分约 2.4% 的时间差算作码表节省。50 个实际生成请求都核验了服务端分类旁路事件。

## 边界

这是受控编辑阶段的闭环证据，不是完整 Agent 越用越快或任意程序的语义泛化。它没有重新验证前轮所有 19 类裸候选选择任务，也不声称把那些任务都改成了成功命中。改进方式是对没有适用性依据的缓存拒绝复用，而非继续扩大高置信度猜测。

当前只学习 compact_edit 支持的生成操作；普通 edit/write 任意输出不会自动入表。类型绑定依赖已有完整 CLI 解析器；其他请求只能在配置检查后精确复用。检验源代码之外的环境依赖仍需要项目检查覆盖。验证命令变化会拒绝原泛化条目，现有条目不自动升级验证来源。

## 验证与使用

334 项测试通过，覆盖持久化冷暖、新参数、无验证不入表、验证失败回滚、验证来源变化、以及高置信度否定/复合请求拒绝。服务镜像和启动时间前后一致，无重启或补丁安装，健康 HTTP 200，临时 SSH 隧道关闭。

```sh
export PIJIT_SAFE_CODEBOOK=1
export PIJIT_VERIFY_CMD='python -m unittest discover -s tests'
# Then launch Pi using the existing project integration.
```

检查命令应覆盖当前请求的行为。此模式与 schema/JIT action 模式互斥；原 `PIJIT_DISABLE_CODEBOOK=1` 优先禁止入表和复用。

```sh
python benchmarks/benchmark_safe_codebook.py --url http://127.0.0.1:8000 \
  --out results/experiments/NEW_SAFE_CODEBOOK --repeats 2
```

正式结果位于 `results/experiments/safe-codebook-loop-20260919-b/`，含每次入表前后快照、请求、产物、检查脚本和源快照。准备阶段首次运行因输出父目录未创建退出，尚无模型请求；原记录另存 `safe-codebook-loop-20260919-a/`，未覆盖。派生指标见 `docs/SAFE_CODEBOOK_RESULTS.json`。
