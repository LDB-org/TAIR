# 区域引用与原生 Pi edit 对照

2026-09-18，使用现有 DeepSeek-V4-Flash-Vision-Exp / vLLM 与本机 Pi 0.85.1。

结论：版本绑定的区域引用确实可以减少重复输出旧代码。在三类调试用例各两次的实际修改中，
输出 tokens 合计减少 **35.14%**，输入+输出合计减少 **8.00%**，双方均 **6/6** 通过验收。
但冻结协议后新增的一项用例中，双方都改对，区域版输出反而从 **276 增加到 464 tokens**。
当前单区域接口不适合替代所有原生 edit 操作。

## 实验范围

这是单次编辑操作的配对实测：实际模型推理、修改文件、运行测试，不是完整自主多轮 Agent 任务。
每个修改用例从同一份已有扫描器开始，每次只提交一个推理请求；不让模型读取测试源码、不手工修补生成代码。
三类任务为：CLI 拒绝非有限 timeout、端口范围支持 /STEP、socket 生命周期改用 context manager。
它们各自的新增测试先在原文件上失败，修改后必须通过新增检查及原有 **17 个 unittest**。
所有执行位于 bubblewrap 私有网络和文件系统 namespace，只使用 loopback。

原生路径使用 vLLM native tools API，参数 Schema 从真实 `createEditTool` 导出，结果交给 Pi 的
实际 `edit` 实现执行，保留其匹配规则；可在同一次调用中提交多个 `oldText/newText` 替换。
区域路径为每个非空行及 AST statement 建立版本绑定的区域，共 190 个候选。
vLLM regex 限定候选 ID，随后生成 replacement；本机运行时根据原文件 SHA256 检查版本并应用修改。
这是生成阶段的有限选择约束，未新增分类头或训练模型；ID 可能由多个 token 组成。

最终协议使用 `L152` 表示原文件第 152 行，`B12_57` 表示 12～57 行代码块。
多行候选列表和源码行号提供给模型；输入 token 统计包含这些信息和示例，没有隐去协议开销。
replacement 第一行从相对第零列开始，运行时补回原区域基础缩进；后续相对缩进由模型生成。
版本不匹配、未知区域、输出截断都会拒绝，相关单测通过。
结构约束不能保证区域语义正确、Python 正确或修改符合用户意图，这些仍依赖实际验收。

双方 temperature=0、max_tokens=4096、thinking 关闭，逐请求新 cache salt。
每个用例第一轮 native→region，第二轮 region→native，共享模型服务器上的其他业务未隔离。

## 开发过程与失败记录

证据目录均为 `results/experiments/pi-region-edit-20260918-<字母>/`，没有覆盖旧输出。

| 目录 | 状态 | 原生验收 | 区域验收 |
|---|---|---:|---:|
| a | 验收脚本 import path 错误，发现后终止；不可用于模型正确率 | 不统计 | 不统计 |
| b | 不透明 R 序号、模型自行生成绝对缩进；首轮后终止调试 | 3/3 | 0/3 |
| c | 改为直观行号/块范围、运行时基础缩进；首轮后终止调试 | 3/3 | 1/3 |
| d | 加入无关 toy 格式示例；双方均在源码后重申当前任务 | 6/6 | 6/6 |
| e | 冻结 d 的协议与提示规则后新增 ASCII 端口校验任务 | 1/1 | 1/1 |

b/c 的失败包括区域选错、缩进错误、原样复制未修改函数等。grammar 合法不代表完成任务。
d 的三个任务参与了调试，不能当作未经调试的泛化集；e 只有一个新增任务，也不足以推断生产正确率。
提前终止的进程可能留下只有 request 的未完成目录；汇总只把有 result.json 的请求计为已完成，
不把未完成请求当成功、零 token 或低延迟样本。

## 实际生成的 tokens

d 每个任务两次，两次间有个别 token 差异：

| 任务 | 原生输出 tokens | 区域输出 tokens | 每任务输出降幅 |
|---|---:|---:|---:|
| 非有限 timeout 校验 | 153 / 153 | 53 / 53 | 65.36% |
| 带步长的端口范围 | 1097 / 1095 | 807 / 805 | 26.46% |
| socket context manager | 228 / 228 | 99 / 99 | 56.58% |

| 六次请求合计 | 原生 | 区域 | 降幅 |
|---|---:|---:|---:|
| 输入 tokens | 14586 | 14220 | 2.51% |
| 输出 tokens | 2954 | 1916 | **35.14%** |
| 输入+输出 tokens | 17540 | 16136 | **8.00%** |

六次请求的推理传输墙钟时间合计 94.77 s → 54.65 s；引擎首末 token 间隔合计
33.11 s → 22.33 s，排队合计 52.82 s → 23.36 s。时间不包含本地应用补丁与测试，
共享负载与输出内容差异仍在，不能把 42.33% 墙钟下降宣称为稳定的算法加速。

## 新增用例的反例

e 要求单端口和范围端点拒绝 `+80`、`8_0`、Unicode 数字等，同时保留 ASCII 范围与周围空格。
双方均通过新增检查和原 17 项测试，但：

| | 原生 | 区域 |
|---|---:|---:|
| 输入 tokens | 2459 | 2398 |
| 输出 tokens | **276** | **464** |
| 输入+输出 tokens | 2735 | 2862 |

原因可直接从补丁确认：原生 edit 一次提交两个局部替换，分别改范围端点与单端口的解析；
当前区域协议一次只支持一个连续区域，模型选了整个 `B12_57` 函数，重复生成中间不变的代码。
因此输出增加 **68.12%**，总 token 增加 **4.64%**。
后续已实现并测试同一次调用内多个不重叠区域，见 [多区域实验](PI_MULTI_REGION_EDIT_EXPERIMENT.md)。
它减少了局部编辑输出，但模型失败与重试输入成本仍限制整体收益。

## 保持最终文件完全相同的编码核验

另对 b 中三份已通过验收的原生补丁进行重编码：程序在候选区域里找到能复现修改的最小区域，
生成候选帧并用运行时还原，要求与原生修改后的完整文件逐字一致，然后用同一模型 tokenizer 计数。
计数为 frame tokens + 实测 EOS token ID 1。这是已知答案后的编码核验，不是模型选区成功率或实际加速。

| 最终文件保持相同 | 原生实际输出 | 区域重编码输出 | 减少 |
|---|---:|---:|---:|
| timeout | 149 | 37 | 75.17% |
| /STEP | 669 | 394 | 41.11% |
| socket | 228 | 100 | 56.14% |

这说明内容引用本身确有压缩空间，同时不能用理想重编码数字代替模型真实运行结果。

## 文件与复现

- `deploy/region_edit_protocol.py`：目录构建、grammar、版本检查与确定性基础缩进。
- `integrations/pi/apply_edit.mjs`：调用实际安装的 Pi edit。
- `benchmarks/compare_region_edits.py`：实际请求、应用修改、隔离验收。
- `benchmarks/region_edit_same_content.py`：最终文件完全一致的重编码诊断。
- `tests/test_region_edit_protocol.py`：过期版本、非法/截断帧、内容边界与缩进验证。

```sh
python benchmarks/compare_region_edits.py \
  --out results/experiments/pi-region-edit-NEW \
  --readable-regions --examples --repeats 2 \
  --cases finite_timeout range_step socket_context
```

新增任务另以 `--cases strict_ascii_ports --repeats 1` 执行。所有输出目录必须不存在。
精确请求、响应、usage、原生 metrics、区域表、文件快照、验收结果和源文件快照保留在各目录。
原有模型/镜像沿用 [Pi 编程实验](PI_ENGINE_TOOLCALL_EXPERIMENT.md) 的版本，未修改现有推理服务配置。
本轮仓库 51 项 pytest、原 raw SHA256 校验、69 项 published claim 校验通过。
