# 短引用复用核对：实验与撤回

2026-09-21。本轮尝试将既有复用核对扩展到普通 write 短引用：content 可以先生成
requirement_check，再选择 stored 索引或 generated 全文。完整字符串生成仍合法，
不增加模型请求，执行前剥离核对元数据；日志单独记录模型核对说明和最终选择。

在线实验没有证明该扩展可靠。两次实际引用都不符合任务，模型甚至可以写出否定判断
后仍选择引用。因此已撤回本轮新增协议、提示、诊断函数、专属测试和 CLI 实验选项，
运行时三个改动文件恢复到 artifact-context-ablation-20260921-a 冻结源码，哈希校验相同。
之前已有的专用复用分支核对、短引用、恢复补录和文件上下文功能不受撤回影响。
冻结失败轨迹、试验源码与本报告保留；不通过检查核对文本中的否定词来放行或拒绝。

## 实际采用与失败

共观察到三次核对决策：

- unique_repeat，专用 reuse_content 分支：核对声称选中 JavaScript uniqueStrings，
  实际所选条目是以 import json 开始的 Python 文件，写入 .mjs 后报 SyntaxError。
  后续恢复才完成。声明与实际条目内容不一致，不能信任模型对条目的描述。
- unique_changed，普通 tool:write 短引用分支：核对明确指出旧实现为大小写敏感，不满足
  新要求，但随后仍输出 stored=0。实际复用旧代码并失败，经过修改和修正测试才完成。
  新增协议确实被使用，但核对说明与决定自相矛盾。
- nullable_changed，专用分支：正确发现旧查询没有排除全 NULL 分组，选择生成新内容，
  产物通过独立 oracle。这是既有专用核对路径，不能证明新增普通短引用路径有效。

审计将每次最初实际写出的内容放入临时副本执行对应 oracle：前两份失败、第三份通过；
原始冻结记录未改动。JSONL 三项均没有采用核对元数据。没有把“没有命中”当成语义判断
正确，也没有把后续恢复成功计作最初引用正确。

实验版本 547 项测试通过，撤回后 541 项测试通过，归档校验通过。未推送、未重启服务、
