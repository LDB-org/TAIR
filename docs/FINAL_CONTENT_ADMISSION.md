# 按执行结束后的文件内容入表

后续扩展：成功 plan 中的 edit 目标也已纳入最终内容观察，见
[edit 恢复学习](EDIT_RECOVERY_ADMISSION.md)。下文记录最初仅 write 的修复范围。

2026-09-20。检查学习路径发现 `complete_tool_plan` 原来直接保存每个 write 的参数。
同一 plan 的后续 edit/bash 可以覆盖或删除文件，但旧内容仍会入表；选中的旧条目也会
累计复用次数。这不符合“学习已执行内容”的口径。

现在完成回调按明确的 write 目标读取最终文件，同路径只读取一次，保存最终 UTF-8
文本，使用二进制读取后解码以保留 CRLF。读取仅针对工作区内的普通文件，每文件最多
读取 1 MiB＋1 字节用于判定超限；超过 1 MiB、缺失、目录、无法读取、非 UTF-8 或解析后
位于工作区外的目标不入表，不阻止已完成工具结果返回。没有扫描整个工作区。

复用条目的内容必须仍出现在这些最终文件中才增加码表复用计数。模板入表也必须与
观察到的最终内容一致。后续命令把旧内容改成新内容时，学习新内容，不奖励已被覆盖的
旧内容。显式禁用复用但保留学习的行为不变，未改变已有条目或清空用户数据库。

新增日志 `final_content_observed`、`final_content_skipped`，后者记录路径和跳过原因。
有 write 但没有可观察最终内容时，入表原因为 `no_eligible_final_content`。

新增七项回归覆盖最终字节/旧条目复用计数、五种不可入表文件状态、模板不一致；原有
入表测试补上真实文件，避免把尚未执行的 write 参数当作完成证据。496 项测试通过，
归档校验通过（2853 个导入文件，61590 个原始校验条目）。本轮未跑 GPU 性能对照。

这是内容观察一致性修复，不是语义验证。所有步骤退出成功不代表每个中间 shell 命令
成功；文件也可能被外部进程并发修改，当前不是事务文件快照。纯 bash 写入和仅 edit
的计划仍未自动学习。既有错误条目没有被这次改动追溯修复。1 MiB 是学习读取的
工程上限，不是文件工具本身的限制，也未证明它是最佳阈值。
