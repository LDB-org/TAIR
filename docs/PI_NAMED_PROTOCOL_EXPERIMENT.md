# 工具名选择协议实验

## 变更与设计

增加可选 `engine_named` 模式，使用真实工具名作为有限选择前缀，例如：

```text
bash
[30]
python3 -m unittest -v
```

引擎仍编译完整的工具集合与参数 grammar，工具执行仍由 Pi 完成。
相对于 `engine_raw`，保留相同的参数布局及命令原始正文优化，只将字母编号替换为真实工具名，
并相应调整格式提示。没有增加独立分类模型，也没有使用原生 Toolcall 回退或代码编辑 DSL。
目标是减少模型从自然工具名到任意编号的映射负担；这是待验证的假设，不是已经证明的错误根因。

命名工具标识必须满足有限字符规则，进入 regex 时转义；非法名称、未知工具、多个有界帧拒绝解码。
原始字符串中的工具帧文本仍只是参数内容，不能被分发成额外调用。
默认 engine 模式未改变，Pi 安装及共享推理服务均未修改。

## 冻结实验

`benchmarks/evaluate_pi_named.py` 使用新的 `statistics_app.py` fixture，要求实现列表 count/total/min/max，
覆盖空输入、负数、重复值、小数、输入不变和 JSON CLI。没有提供实现。
要求实际调用当前 Pi 的全部 8 个内置工具及 reply_user；PowerShell 缺失错误仍为预期环境限制。
任务含工具覆盖要求，因此不等于自然无提示工具选择评测。

两个协议各运行两条隔离会话，并发均为 2、temperature=0、thinking=false、每会话独立 cache salt。
先运行命名模式，再运行字母模式，不在运行中调整提示。最多 14 次模型调用，避免失败无限消耗。
独立验收检查 6 组函数输入及 CLI，并重跑模型生成的 unittest；所有失败及修复费用保留。
新 fixture 只有一类任务、每组仅两次、配置先后运行且共享服务，无法推出稳定速度或生产正确率。

额外将上一轮重复 read('ls') 的用户消息及前三次调用/错误冻结，分别用两个协议回放两次下一步生成，
仅观察返回调用，不执行工具，也不把它当成整任务成功率。两次重复交替模式顺序。

证据目录：`results/experiments/pi-named-20260918-a/`，包含运行前源码快照、请求历史、逐次响应、
工具事件、生成文件、独立验收，以及单独的失败历史回放。

## 第一轮结果

| 协议 | 全流程完成 | 模型请求数 | 输出 tokens | 总 tokens | 两会话整批耗时 |
|---|---:|---:|---:|---:|---:|
| 字母＋原始命令 engine_raw | 2/2 | 24 | 1790 | 65560 | 120.45 s |
| 工具名＋原始命令 engine_named | 0/2 | 17 | 9396 | 49072 | 125.98 s |

两条命名会话均在 bash 正文反复生成测试命令，达到 4096 输出 tokens 后被截断拒绝，未执行这些命令。
其中一份代码通过了事后独立行为检查，但不能因此算作 Agent 完成任务。
字母组两条会话均完成全部工具覆盖及行为验收。
命名组少发请求只是提前失败，总 tokens 较少不是完成相同工作的节省。

上一轮失败历史的四次冻结回放：字母两次均继续 `read(path="ls")`；命名一次继续错误调用，
另一次生成正确的 `ls` 调用。只能说偶尔摆脱了该重复，不能声称修复或建立可靠成功率。
回放只生成下一步，未执行工具，独立 usage 保存在 replay-results.jsonl，不混入任务对照费用。

为准备后续变体，运行期间仅扩展了本地 runner 接受的模式名称列表；字母阶段实际 runner 另存为
sources/run_scanner.raw-phase.mjs。第一轮远端 worker、工具 Schema、任务、已有模式提示及解码逻辑保持冻结。

## 修订：工具名＋有边界命令

另增加可选 `engine_named_bounded`：保留工具名选择，但 bash/powershell 命令恢复为 JSON tuple 内的字符串。
write/reply_user 的既有原始正文布局不变，没有修改原有工具能力。
有结束边界允许 grammar 在帧完成后拒绝后续命令；不能保证模型绝不在字符串内部重复生成。

修订后在同一任务另跑两条并发会话，证据目录 `results/experiments/pi-named-20260918-b/`。
这是观察第一轮失败后的调试复验，不再是独立盲测，未通过提高预算掩盖失败。

| 指标 | 会话 0 | 会话 1 |
|---|---:|---:|
| 代码独立行为检查 | 通过 | 通过 |
| 全部工具流程及回复 | 未完成 | 完成 |
| 实际模型请求数 | 14 | 14 |
| 输出 tokens | 759 | 865 |
| 总 tokens | 38325 | 37532 |
| 累计生成时间 | 27.775 s | 25.465 s |
| 会话耗时 | 100.76 s | 115.69 s |

两条均有一次编辑匹配错误；会话 0 另有一次 bash 测试失败，会话 1 另有一次预期的 PowerShell 缺失错误。
恢复边界后没有发生本轮命令正文生成至截断的情况。
会话 0 在读文件、编辑、修复和测试上用完 14 次请求，尚未调用 PowerShell 和 reply_user，按失败计。
日志第 15 条是本地轮数上限事件，不是额外模型请求。
会话 1 完成全部工具调用、回复及独立验收。

合计 1/2 完成、28 请求、1624 输出 tokens、75857 总 tokens；整批 115.98 秒。
相比字母组，输出少 9.3%，但总 tokens 多 15.7%，完成率更低，不能称为更优或更快。
所有返回帧重新独立解码，与推理侧返回对象一致；第一轮两个截断响应仍被拒绝。

## 结论与后续范围

工具名不能单独解决协议适配；原始命令的固定参数复制速度优势，也不能直接推广到自主 Agent 生成命令。
当前 default engine 模式仍不变，新增模式仅用于实验。
本轮未再针对该题修改提示或放宽任务成功口径。

下一项值得隔离的是工具历史表示：当前适配器将工具结果转换为带标签的 user 文本，
而非保留原生 tool 消息语义。这是代码事实；它是否造成重复编辑与恢复困难仍是待测假设。
应该对固定历史做原生工具历史与当前编码的对照，而不是继续只缩短输出或增加并发。

135 项 pytest、原始 raw SHA256 和 69 项 published claims 校验通过。
结果及源码快照使用各自独立 SHA256SUMS；未修改共享推理服务、全局 Pi 配置、权重或原论文主结论。
