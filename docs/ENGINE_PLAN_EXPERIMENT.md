# 引擎内分类构建 plan：最小验证

2026-09-19，在 Yuesheng 现有 5090 服务完成 54 次有限任务测试。没有安装补丁、重启服务或启用码表。

结果：引擎内分类与参数生成合并，比客户端拆成两次请求快 19.15%；但比一次生成整个计划慢 20.90%。这不支持直接把现有批量规划替换为本原型。

## 实际实现范围

调用方只接收 `plan` 包装。内部分类选择 read、replace 或 write 家族，然后按对应 schema 生成参数；一次计划可含多个同类操作。生成结束后，外部执行器顺序读写文件，出错停止。未观察源码的题目要求返回 read，不能假设源文件内容。

复用已有 `/v1/openjev/toolcall`：分类直接取候选 logits，服务端保留请求 KV，继续生成参数。18 次引擎路径均在服务日志找到 sampler bypass、暂停与恢复事件，恢复前后 KV block IDs 和 computed_tokens 相等。

**这只是一次内部分类加参数生成的最小原型。** 尚未实现异构多步骤计划的逐动作/逐参数分类状态机，未把新 `/plan` 路由安装到服务，也没有接入完整 Pi Agent。计划包装和工具目录仍由测试客户端提供；不能称为完整实现了用户提出的引擎内计划编译器。

## 对照

六类任务：默认值修改、两个文件修改、函数求和修复、创建单文件、创建双文件、缺少源码观察时先读文件。每类每组重复三次，以固定随机顺序交错运行。

| 路径 | 验收通过 | 总秒数 | 中位秒数 | 生成 token | 分类控制记录 | 推理 API 请求 |
|---|---:|---:|---:|---:|---:|---:|
| 一次生成整个计划 | 18/18 | 15.227 | 0.770 | 717 | 0 | 18 |
| 客户端分类后另请求生成 | 18/18 | 22.768 | 1.232 | 594 | 18 | 36 |
| 引擎内分类、保留 KV 续接 | 18/18 | 18.409 | 0.985 | 612 | 18 | 18 |

计时包含计划 HTTP、外部执行、独立产物/行为检查，不包含预先统一完成的 tokenization 和初始文件恢复，不是完整 Agent 耗时。没有排除首次调用，没有挑选成功样本；全部 54 次保留。只读题的成功代表正确停在观察边界，不代表修复整个任务。

分类两组共用相同准备好的分类消息与续接内容，schema 相同；生成组看到相同任务、观察和动作目录，但输出完整 kind/arguments，输出指令与表示不同。因此是实现路径比较，不是只改变一个 GPU 算子的实验。两种分类路径的实际生成 token 不完全一致，说明输出轨迹也有差异。

每次尝试使用新缓存命名空间；客户端拆分的两个阶段共用 namespace，允许前缀缓存。引擎组保留同一请求 KV。逻辑输入 token 分别为 7218、16464、9192，不等于未缓存的 prefill 计算量。未测模型前向次数，不能拿 API 请求数代替；这些计划较短，也未证明长上下文、并发或真实仓库任务的收益。

## 判断

把两个客户端请求合并进引擎确实节约了本轮时间，但只分类工具类型减少的输出很有限：生成组 717 token，引擎组仍生成 612 token，另有 18 条分类控制记录。引擎仍需要分类阶段、注入续接指令和生成参数。当前结果与这些额外成本抵消 token 节省一致，但没有精确分离各项 GPU/调度成本。

要继续验证原设想，应让分类结果直接绑定已知路径、操作及参数，省掉更长的输出，并测量内部每次状态切换成本。不能从本轮推出逐字段分类必然更快，也不能从本轮否定尚未实现的完整设计。

## 复现与校验

```sh
python benchmarks/benchmark_engine_plan.py --url http://127.0.0.1:8000 \
  --out results/experiments/NEW_ENGINE_PLAN --repeats 3
```

需要已有实验分类/续接接口的服务。无需安装补丁。原始请求输入、响应、产物、版本、服务事件和审核脚本见 `results/experiments/engine-plan-20260919-a/`。

318 项本地测试通过；原有 23802 条归档校验通过。执行器路径逃逸、错误后停止、原始错误函数被独立验收拒绝均有回归测试。容器启动时间和镜像与测试前一致，末次健康检查 HTTP 200，临时 SSH 隧道已关闭。
