# 复用约束的定向修复（2026-09-20）

本轮针对长源码新增内容、完整模板遗漏额外验证两项实际反例。没有清空
~/测试 的 ~/.pijit 码表，没有重启引擎，模板仍仅在实验显式开启、日常默认关闭。

## 实现

1. 用户请求含 Markdown 三反引号代码块时，候选的完整内容必须逐字等于其中一个块。
   内容模板检查源文本，完整 plan 模板检查其内嵌源文本。不同内容在分类前排除，
   日志以 payload_mismatch_candidates 记录排除数。不是关键词触发执行，不增加模型请求。
2. 用文本差异突出历史任务与当前请求的变化，仅加入被选分支的续写指令。
   新增要求必须追加操作或退回生成。无另外的模型总结调用。
3. 差异比较关闭 SequenceMatcher 的 autojunk，防止大量重复行掩盖真实变化；
   超过 6000 字符时显式标记中间省略。完整当前需求仍保留在原始上下文。

这是保守的内容复用门槛，不是通用语义验证器。代码块仅是示例时也可能失去复用机会；
未用三反引号表达的内容、自然语言新增约束、多个代码块与不同文件的对应关系尚没有
通用机械验收。生成路径本身仍可能错误。额外操作依靠差异提示，本轮通过不代表保证。

## 保留的失败尝试

仅在分类目录和续写中重复突出差异的 request-delta-template-guards-20260920-a：
新增源码仍误复用（失败），额外操作通过；输入成本也明显增大。该方案未保留为最终
目录提示，最终版本只在续写阶段给出差异，并在分类前机械排除不一致的显式内容。
旧版 unified_diff 在重复行用例上被单元测试抓出差异截断问题，随后改为关闭 autojunk。
