# 外层搜索与调用优化

## 实现

新增可选 `PIJIT_PLANNER_EFFICIENCY=1`，默认关闭。混合原生规划器现在可接收工作区根目录、最多 64 个根条目和明确的项目内搜索提示：优先读取用户指定路径，缺失时在项目内搜索，除非用户明确要求，否则不扫描系统根目录或主目录。提示合并已确定的操作和所需检查；代码未改、检查未失败且需求已覆盖时不重复检查。pytest 提示关闭 cacheprovider，测试数据放临时目录。

用户消息开头精确符合 `Read path.` 时，桥接层在确认文件存在、大小不超过 200 KB、解析后位于工作区内后，直接发出 read 调用，无需模型决定这次读取。它不跳过读取、不会越过失败结果自动编辑，也不把模糊/否定意图解析成指令。越界与 symlink 越界均拒绝直达。其他句式仍由模型处理。

搜索和检查合并是提示约束，不是 shell 命令拦截或操作系统沙箱，不能保证阻止任意形式的外部遍历。明确读取直达是确定性路径；码表命中依然不代表语义验证完成。新增回归检查路径/意图边界、零推理读取和对照配置隔离。

## 同场对照

64 次尝试：Rich v13.7.1 (`7f580bdcf07a3b269a0e786b6a3aa9c804f393cf`)，4 组 × 2 次独立重复 × 8 步。`hybrid` 与 `hybrid_unoptimized` 仅外层效率开关不同；前者与 `hybrid_no_book` 仅码表开关不同。原生基线保留普通 tools API，多工具开启，没有给它添加新提示。四组顺序随机交错。

沿用默认值、短别名、UTF-8 读取和负数校验四类任务。每次重复从空表开始，热轮恢复原始源码，独立隐藏 oracle 不提供给模型或用作运行时验证。夹具与 oracle 未变，继承此前预检证据。Pi 和工具在本机 macOS 隔离环境运行，模型请求通过 SSH 发往 yuesheng 既有 5090 服务；没有重启或修改服务。

完整计时含 Agent 启动、模型请求、工具、检查、回复和外部验收，不含夹具准备和后验复验。编辑 bridge 时间不含启动 Python 进程。每题 120 秒上限、每次回复 2048 token。原始记录与第三方源码仅本地保留，所有尝试均计入，没有重跑替换。

## 结果

**64/64 完整任务通过，64/64 保存产物复验通过。全部 usage_complete=true，无超时，无无关文件违规。**

| 指标 | 原生多工具 | TAIR 原外层＋码表 | TAIR 新外层、无码表 | TAIR 新外层＋码表 |
|---|---:|---:|---:|---:|
| 完整总秒数 | 290.708 | 239.219 | 210.987 | 200.477 |
| 单次中位秒数 | 11.782 | 11.211 | 10.893 | 11.304 |
| 外层模型请求 | 107 | 90 | 68 | 72 |
| 编辑模型请求 | 0 | 4 | 12 | 4 |
| 输入 token | 451262 | 336893 | 275974 | 285304 |
| 生成 token | 26763 | 19181 | 15766 | 15315 |
| 分类控制记录 | 0 | 4 | 12 | 4 |
| 码表命中 | 0 | 8 | 0 | 8 |
| 恢复后的工具错误记录 | 3 | 8 | 1 | 0 |

同样启用码表时，新外层总时间 **239.219 → 200.477 秒，观察到下降 16.20%**；外层请求 **90 → 72（下降 20%）**。但两次重复结果分别是：

| 独立重复 | 原外层＋码表 | 新外层＋码表 |
|---|---:|---:|
| 第一次 | 132.824 秒 | 93.011 秒 |
| 第二次 | 106.396 秒 | 107.466 秒 |

收益主要集中于第一次，第二次略慢，单次中位数也未改善；不是稳定的普遍 16% 提速。与原生组 290.708 秒相比，新外层＋码表组为 200.477 秒，观察值约少 31%；这包含规划接口、路由、码表及不同验证轨迹的共同影响，不能归为单个机制或模型解码加速。

### 调用减少来自哪里

优化后的两个 TAIR 组各有 **12 次明确读取直达**，每次均无模型请求。开启码表的新外层组 bash 工具调用从原外层的 **46 次降到 39 次**；read 调用反而从 22 增到 24，说明仍存在重复读取。不能把所有 bash 调用一律归为冗余，也不能声称所有额外调用已经消除。

UTF-8 完整耗时：

| 独立重复 | 原生 | 原外层＋码表 | 新外层、无码表 | 新外层＋码表 |
|---|---:|---:|---:|---:|
| 第一次 | 72.138 | 48.332 | 24.969 | 15.356 |
| 第二次 | 51.820 | 28.098 | 29.482 | 36.907 |

第一次原外层反复执行分散检查，优化组减少了往返；第二次收益没有复现。**本轮四组均未观察到直接 `find /` 调用**，所以不能把本轮速度差算成搜索范围提示的独立收益，也不能声称“只有优化组杜绝了全盘搜索”。上轮的两次全盘搜索超时未在本轮重现，提示的长期可靠性仍需更多任务验证。

### 码表与热任务

两组启用码表的 8 个热任务均命中且正确。新外层下，关闭码表的热编辑 bridge 合计 **10.390515 秒**，开启后 **0.097379 秒**；编辑请求 8→0。完整热任务仅 **87.272840→83.793964 秒**，约少 3.99%，开启组外层请求 29→34，仍抵消了部分内部收益。

同样启用码表时，原外层热任务 83.879644 秒，新外层 83.793964 秒，几乎不变。外层优化的本轮总收益主要来自冷任务/通用任务的轨迹差异，不是热复用普遍再次加速。预先设计的重复率不代表生产命中率。

## 验证与复现

356 项测试通过，完整存档校验通过。20 个结构化生成请求均核对到引擎旁路事件。服务启动时间、镜像、tokenizer 摘要和健康状态前后一致；临时 SSH 隧道关闭，上游检出无修改。

公开汇总：`PLANNER_EFFICIENCY_RESULTS.json`；工具轨迹计数：`PLANNER_EFFICIENCY_CALLS.json`。原始证据：`results/experiments/three-goals-repository-rich-planner-20260919-a/`。工具分析只读事件，不执行轨迹中的命令；根搜索检测覆盖直接 shell `find /`，并非所有遍历写法。

报告工具扩展为接受由配置确认码表开启的对照组，增加 `--frozen-sources`，用于核对存档源码而无需当前 checkout 完全一致。本轮运行结束后才修改报告工具；实验运行时的源码快照不变。新分析器及报告工具另存审计源码，全部纳入校验。

```sh
python benchmarks/benchmark_three_goals.py --url "$URL" \
  --tokenizer-revision "$VERIFIED_REVISION" \
  --repository /path/to/rich-v13.7.1 --repository-suite rich \
  --safe-codebook --planner-efficiency \
  --out results/experiments/three-goals-repository-NEW \
  --cases rich_json_default rich_json_short_alias rich_json_utf8 rich_filesize_negative \
  --rounds 3 --repeats 2 --warm-cases rich_json_default rich_json_short_alias \
  --arms native_multi hybrid_no_book hybrid hybrid_unoptimized
```
