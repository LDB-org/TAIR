# 多操作计划实测（2026-09-19）

**一次外层响应处理多个操作可行，推理次数明显减少；本组完整任务有提速，但幅度有波动。**
实现仍为 `PIJIT_BATCH_TOOLS=1` 实验开关，默认关闭。没有替换线上部署或重启 vLLM。

## 最终代码复测 C

三个场景：多属性修改、别名、函数修复并补测试；冷暖各一轮，每组六个完整任务，共 18 个。
暖轮恢复原始源码，保留本组运行状态，不保留对话；计时包括启动、计划、工具、测试、恢复、最终回复和独立行为检查。
使用 Pi 0.85.1 和现有 6×RTX 5090 服务。推理次数包含内层编辑请求，未把本地调度算成模型请求。

| 指标 | 朴素 Pi/vLLM | 当前单步 TAIR | 批量计划 TAIR |
|---|---:|---:|---:|
| 完整任务通过 | 6/6 | 6/6 | 6/6 |
| 总耗时 | 66.29 秒 | 62.58 秒 | **53.76 秒** |
| 推理请求总数 | 38 | 36 | **22** |
| 其中外层模型请求 | 38 | 32 | 20 |
| 生成 tokens | 5,974 | 2,325 | 3,133 |
| 分类控制记录 | 0 | 36 | 22 |
| 输入 tokens | 84,524 | 95,702 | 62,894 |
| 分词 HTTP 请求 | 不单独调用 | 123 | 62 |
| 编辑码表命中 | 0 | 2 | 0 |

相对单步 TAIR，本轮请求减少 **38.9%**、总耗时减少 **14.1%**；相对朴素组分别减少 **42.1%**、**18.9%**。
批量组完成 14 个多操作计划，实际最长六步。每个完整任务仍需三至四次推理，包含最终回复与可能的内层编辑。

这轮速度收益来自执行流程调整，整套计划仍通过生成产生，**尚未实现计划级码表学习与分类复用**。
批量模式有些修改选择普通 edit，当前编辑码表命中反而减少；不能把结果全归于码表或分类器。
批量组生成 tokens 比单步组更多，减少调用不会等比例减少时间。

## 重复验证与先导轮

| 轮次 | 每组任务数 | 朴素组耗时 | 单步 TAIR 耗时 | 批量组耗时 | 批量组通过 |
|---|---:|---:|---:|---:|---:|
| B：两次独立重复 | 12 | 125.83 秒 | 129.09 秒 | 117.21 秒 | 12/12 |
| C：最终代码复测 | 6 | 66.29 秒 | 62.58 秒 | 53.76 秒 | 6/6 |

B 轮单步 TAIR 有一次遗漏要求新增的测试，判为失败（11/12），其耗时仍计入；朴素组和批量组均 12/12。
B 中批量组比朴素组总耗时低 **6.8%**，请求从 76 次降到 43 次。
C 之前仅将 jsonschema 改为按需导入，避免非批量路径支付无用的启动成本（本地测得每进程约 28～30 毫秒）。
两轮的耗时差异不能全归因于该小改动，也没有将不同轮次合并宣称一个固定加速比。

[B 轮报告](../results/experiments/batch-tools-agent-20260919-b/REPORT.md)保留完整输入输出、源码、错误及恢复记录。
[先导 A 轮](../results/experiments/batch-tools-agent-20260919-a/REPORT.md)仅把批量工具加入候选，模型一次也没有选择它；
因此后来改为将支持的外层操作统一编码成操作列表，而不是继续等待模型主动切换。
A 中遗漏新增测试的一次失败同样保留。

## 执行方式与限制

- 外层模型选择最终回复，或返回包含 1～8 个操作的计划；可以把读取、已知编辑和测试合并。
- 使用原生 Pi 工具工厂和工具钩子，批量模式按顺序执行；任一步失败或被阻止，后续步骤停止。
- 先前已经成功的修改保留，不提供整个计划的事务回滚；模型根据实际结果继续处理。
- 整体计划先校验工具名和参数 schema；这不能证明参数在语义上已经具备执行条件。
- 明确语句的本地单步调度在批量模式中关闭；紧凑编辑内部仍保留分类、生成回退和校验入表。

**模型仍会猜测依赖未读结果的操作。** C 中出现四次不存在路径的读取、两次空 oldText 编辑错误，
随后九个操作被执行器阻止；最终任务全部恢复完成，代价已经计时。B 中也保留了相同类型的错误。
因此应继续明确“读取阶段”和“执行阶段”的边界，而不是假设任意任务都能一次调用完成。

[本地执行探针](../results/experiments/batch-tools-execution-20260919/REPORT.md)使用真实 Pi、模拟模型输出，
验证顺序执行和错误后的停止；它不属于 GPU 性能结果。

284 项仓库测试通过。C 轮全部项目通过独立 unittest 复跑，58 个分类请求都有引擎 sampler-bypass 证据，
源码快照与最终实现一致；临时隧道已关闭。历史与本轮归档保留校验和。

这是共享后端上少量手写任务的实现对照。朴素组沿用此前单工具基线设置，包括 `parallel_tool_calls=false`，
没有另测开启原生并行工具调用的基线。工具目录、提示、语法和控制粒度均有差异，不能外推为普遍加速或独立分类器收益。
使用配置见 [Pi 说明](../integrations/pijit/README.md#experimental-multi-operation-plans)。
