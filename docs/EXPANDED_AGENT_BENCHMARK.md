# 扩大 Agent 测试：120 次完整任务（2026-09-19）

**扩大后发现严重回归：当前上下文约束版不能依据上一轮小样本结果推广。**
新增的 `oldText.minLength=1` 与部署中 xgrammar 0.2.3 存在已复现的兼容性缺陷，
大量精确编辑无法生成正确跨度，随后陷入重复失败。此次没有中途修改 Agent 实现或替换失败样本。

## 范围与口径

10 类合成任务 × 2 次独立重复 × 冷暖两轮 × 3 组，共 **120 次**，每组 40 次。
在原有属性、别名、函数修复之外，增加跨文件功能及文档/测试、嵌套包、CSV、JSON 配置、
异常处理、跨模块行为和一个包含 80 个无关模块的 84 文件项目。
七类新增题目的判定器均先通过反例与参考实现预检。

同一现有 6×RTX 5090 服务、Pi 0.85.1，逐任务顺序执行、组间交错。
冷暖两轮都恢复原始项目并创建新会话，暖轮只保留本组运行状态。
每次 Agent 最多 180 秒；失败、恢复、工具、测试、最终回复和独立判定都计时。
事后的测试质量审核与环境取证不计入 Agent 时间。没有重启或替换服务，临时 SSH 隧道已关闭。

## 定位到的具体缺陷

部署容器中的 xgrammar 0.2.3 将带 `minLength=1` 的字符串编译成了不包含 JSON 转义分支的语法。
CPU 匹配探针显示：包含双引号、换行、反斜杠的三个合法非空值，不加 minLength 都能接受，
加上后都被拒绝；Python jsonschema 独立验证它们均符合原始 schema。
所以这个约束会使部分正确 oldText 无法生成，而不只是让模型“更谨慎”。

这解释了大量去掉引号、截断多行跨度、反复编辑不变内容的现象。其他工具或更短跨度有时能绕过，
但不能保证恢复，也不能将每个语义错误都归因于这一缺陷。
按工具名和参数计，新组记录到 855 次同一任务内重复的失败调用，单个调用最多失败 97 次，另有 457 个后续步骤被阻止。
该计数不保证每次文件状态也相同；重复测试可能发生在真实修改之后。
还需要处理重复失败的终止/重新读取，以及独立的 CSV 语义错误。

[最小复现与说明](JSON_STRING_GRAMMAR_COMPATIBILITY.md)。目前尚未修复并重跑这条约束，
新模式保持默认关闭；本报告没有声称修复后的速度或成功率。

## 证据与限制

- 290 项仓库测试通过，但部署语法兼容性探针有 **3/10** 个不一致，说明普通 schema 单元测试不能代替后端语法测试。
- 1146 个成功返回的 TAIR 请求全部有引擎 sampler-bypass 证据；失败/中断请求保留原始记录，不冒充完整用量。
- 全部运行源码快照匹配；原有测试完整性检查通过。独立 unittest 复跑保留原始失败，未修补任务产物。
- 12 个函数修复结果新增的测试均能捕获负数 total 和输入原地修改故障。CLI 审核使用副本，兼顾直接调用 main 与启动脚本；仅校验返回 None 的弱断言被识别。
- 审核器第一次只替换脚本入口且缺少原测试 Python PATH，随后修正；初稿及原因保存在 audit-diagnostics，未影响模型输入、原始耗时或运行结果。
- 这是合成场景，不代表真实大型仓库、并发吞吐、长上下文或长期跨任务码表泛化。旧批量组也没有达到全部任务正确。
- 朴素组是同一补丁服务器的普通 tools API，沿用 `parallel_tool_calls=false`；没有单独测试无补丁引擎或开启原生并行工具的基线。
