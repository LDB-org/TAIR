# SQLite 码表与检索规模测量

2026-09-20，plan 码表改为 SQLite 持久化和 FTS5 词面检索，取消默认 256 条截断。每次仍最多提供 15 条候选，另留 GENERATE；此限制属于现有引擎接口，不限制磁盘存储总量。

## 数据与兼容

- Pi 工作区状态使用 `plan-codebook.sqlite3`。数据库存源码、契约、源码哈希、验证证据、格式版本、验证成功次数、成功复用次数和最近使用时间；索引只包含契约。未改变 compact-edit 的旧码表。
- 传给 `PlanBook` 的旧 `.json` 路径映射到同名 `.sqlite3`。首次使用在事务中导入旧 JSON 和契约拒绝记录，验证源码及身份哈希、编译源码，原文件保留不改。迁移失败回滚，可修复旧文件后重试；迁移成功后不再读取旧 JSON。不要同时运行仍写旧 JSON 的旧客户端与新客户端；迁移不是双向同步。
- 入库、去重、拒绝和维护通过 SQLite 事务串行提交，连接超时 30 秒；并发首次初始化也在事务中序列化。使用标准库 sqlite3，运行环境需启用 FTS5。未增加数据库服务器或服务重启要求。
- 查询不再调用全量 `load()`，只校验返回候选的源码和身份哈希。`load()` 保留为显式导出/完整检查接口。首次迁移仍需要读取并检查旧码表。
- 以 BM25 排序，复用次数、验证次数与最近使用时间用于同分排序。中文额外索引相邻双字。查询最多取 128 个去重词，契约词优先。零匹配时直接提供 GENERATE，不再用无关条目填满 15 个位置。
- 拒绝按条目 ID 和完整契约哈希隔离，不再在第 257 次拒绝时遗忘旧记录。验证并成功发布后才累计复用次数；单纯进入候选、被模型选中或验证失败都不算成功复用。

默认不自动删除条目。磁盘需要维护时，可显式调用：

```python
from plan_book import PlanBook  # deploy/ 在 Python import path 中
book = PlanBook('/path/to/plan-codebook.sqlite3')
removed = book.prune(100_000)
```

维护优先保留当前条目格式、成功复用较多、验证次数较多、最近使用的条目；同时清理被删除条目的索引及拒绝记录。这里的版本指条目格式，并非已实现依赖环境自动兼容判定。SQLite 删除可回收页供后续入库使用，不承诺数据库文件立即缩小。

## 本地规模测量

原始报告及源码快照：[plan-book-scale-20260920-a](../results/experiments/plan-book-scale-20260920-a/report.json)。macOS arm64、Python 3.11.16、SQLite 3.53.4，C1；每种查询 31 次，首轮单独记录，下表为后 30 次中位数。每次重新连接数据库，没有清空操作系统文件缓存。

| 存储条目 | 稀有词查询 | 常见词混合查询 | 数据库大小 |
|---:|---:|---:|---:|
| 256 | 0.156 ms | 0.349 ms | 151,552 bytes |
| 10,000 | 0.167 ms | 7.360 ms | 3,801,088 bytes |
| 100,000 | 0.167 ms | 70.704 ms | 37,822,464 bytes |

数据是编译通过的合成常量模块，目标条目在全部查询中被召回。这只测存储和词面检索，不证明语义适用率。常见词查询命中大量文档，评分和排序开销仍随匹配范围增长。真实长源码的磁盘占用会更大。

本轮没有 LLM/GPU 请求，生成 token 和分类控制记录均为 0；没有重跑完整 Agent 或旧 JSON 对照，不能据此宣称端到端提速。过去的 5090 报告属于其各自源码快照。语义改写召回、海量真实契约、在线命中率仍需单独评测；条目变多不保证收益单调增加。

393 项仓库测试通过，覆盖旧库迁移与回滚、跨进程并发初始化/入库、超 256 条保留、拒绝记录持久化、中文检索、显式清理、成功复用统计及 Pi 统计接口。输出文件与数据库仍不是跨资源原子事务；已有多文件发布中途失败的限制没有在本轮解决。
