# 冻结多区域协议的新任务筛查

2026-09-18。这是从先前调试任务之外选取新需求的首轮筛查，不是生产认证。

## 预先固定的方法

- 6 类任务：四个短参数别名、紧凑 JSON、空输入跳过 DNS/线程池、重复端口只扫描一次、socket 创建失败返回 False、禁止长参数缩写。
- 每类重复两次，共 12 对。任务顺序使用 seed=20260918 打乱，原生/混合先后次序交替。
- 协议提示沿用上轮快照；grammar 使用开跑时本地版本，之后不按结果调参。manifest 和 sources 保存请求模板、任务及代码。
- 原生方案调用真实 Pi edit 一次。混合方案先用多区域，遇到结构错误、语法错误或测试失败，恢复原始文件后最多调用一次原生 edit。无额外区域重试。
- 回退使用原任务与原文件，重新发起真实推理，不复用对照组答案。两组每个请求均使用新 cache salt，temperature=0、thinking 关闭、max_tokens=4096。
- 成本累计所有失败与回退。完整耗时包括请求、应用修改、隔离任务检查及原有 17 项 unittest；不包含实验初始化及预检。
- 新增检查在原文件上均须失败。模型仅收到任务，不收到测试源码；测试作为回退判断的 oracle，这比没有测试的真实任务条件更理想。
- 执行处于 bubblewrap 私有网络，仅使用 loopback，不扫描外部目标。

事先选定的筛查线：成功数不低于原生、平均完整耗时至少降低 15%、按任务类别聚类 bootstrap 的降幅 95% 区间下界大于零、P95 不高于原生。
只有 6 个相关任务，置信区间也只能作描述性参考；即使全部满足，也需要更多项目、独立任务、不同负载和重复窗口验证。

## 版本与证据

使用现有 yuesheng DeepSeek-V4-Flash-Vision-Exp 服务和本地 Pi 0.85.1，未重启或修改模型服务。
原始证据：`results/experiments/pi-region-holdout-20260918-a/`。
驱动程序：`benchmarks/evaluate_region_holdout.py`；汇总：`benchmarks/summarize_region_holdout.py`。
每个任务保存各次真实请求、响应、usage、metrics、应用结果、隔离测试结果和修改文件。

## 能回答与不能回答的问题

这轮回答：冻结协议后，在新编辑任务上，算上原生回退是否仍节省 tokens 和时间。
它不覆盖完整自主 Agent 任务、连续长时间运行、服务故障注入、并发文件提交、权限控制及重试幂等性。
这些生产条件仍未通过本轮证明。共享 GPU 的排队变化也不能归因于协议本身。

## 实测结果

| 指标 | 原生 Pi edit | 多区域＋最多一次原生回退 |
|---|---:|---:|
| 首轮通过 | 12/12 | 6/12 |
| 最终通过 | 12/12 | 12/12 |
| 模型请求数 | 12 | 18 |
| 输入 tokens | 28572 | 42470 |
| 输出 tokens | 2738 | 2483 |
| 总 tokens | 31310 | 44953 |
| 完整编辑任务累计耗时 | 145.85 s | 146.47 s |
| 单任务平均耗时 | 12.15 s | 12.21 s |
| 单任务 P95 | 26.76 s | 22.42 s |
| 引擎报告累计排队 | 81.69 s | 48.63 s |
| 引擎报告累计生成 | 31.94 s | 56.48 s |

计入全部失败与回退，输出减少 **9.31%**，总 tokens 增加 **43.57%**，完整耗时增加 **0.43%**。
按任务类别聚类 bootstrap，耗时降幅的描述性 95% 区间为 **-70.27%～45.75%**，跨越零。
预设筛查线 **未通过**。P95 在此样本中降低不构成稳定收益证据，尤其混合组本轮排队更少。
引擎报告的生成时间在混合组反而更长；这同时受多次调用、共享负载及解码路径影响，不能据此单独归因。

短参数别名、空输入快速返回、socket 创建异常三个任务各两次都触发回退；六次均为 AST 检查发现缩进错误。
错误补丁未通过验收，不作为成功候选执行。恢复 pristine 后，真实原生调用完成修改并通过测试。
其余三个任务的区域首轮均通过。说明简单单行变化的压缩收益不能外推至更复杂的多行修改。

本轮未在看到结果后调整提示、grammar 或测试。当前结论为：回退在这 12 个任务中恢复了最终成功率，
但请求增加与重复输入吞噬了输出收益，尚无稳定加速证据，也不构成生产可用证明。
下一次优化应优先解决相对缩进可靠性，或在发出请求前可靠地选择适用编辑路径；然后使用另一批新任务检验，
不能继续用本批任务报告独立泛化正确率。

63 项 pytest、原始 raw SHA256 校验及 69 项 published claims 校验通过。
