# 仅复用路由分类：完整 plan 实验

2026-09-20。新增可选 `PIJIT_REUSE_ROUTING=1`。对用户仍只有 plan，内部所有 Pi 子工具可用，动态码表继续学习。

## 变更

分类分支只包含最多两个完整内容候选和通用生成；不再为七个首工具分别创建分类选项、参数 schema 和续写前缀。需要生成时直接生成包含任意子工具的完整 plan。接入现有融合分类内核，不增加外层 LLM 请求，不修改服务端内核或模型权重。恢复仍走专用通用分支。解码阶段显式映射 wire 分类下标到原内容条目，避免错绑码表。

目录回到 system prompt，未启用上一实验的后置目录。当前用户需求在分类指令和生成续写中明确重申，降低历史内容被误当新需求的风险。该机制不是语义正确性的形式证明；分类依然可能误选，后续生成可放弃复用。

与既有基线相比，本实验同时改变候选上限、分类分支及当前需求重申，不能归因到其中一个单独因素。SSH 压缩未启用；朴素组和 TAIR 走相同服务和隧道。

## 方法

同一 yuesheng 服务（6×RTX 5090、DeepSeek-V4-Flash-Vision-Exp、TP2/PP3）、Pi 0.85.1，21 个相同自编任务，两组串行交错。初始码表是用户只读快照，隔离状态中持续学习，未清空用户码表。TAIR 本地 tokenizer、会话缓存开启。两组总输出上限 17408，TAIR 每子工具参数限 2048。150 秒任务上限，失败及恢复均计入总耗时，无测试器重试。产物 oracle 在计时外独立验收。

启动前增加 Pi 版本及路径检查；中断测试时等待子进程退出，再关闭日志和冻结校验清单。此次不重启服务，不改变用户默认配置。

## 结果

全部 42 次运行完成，产物 oracle 再次独立执行，均与原始验收一致。

| 指标 | 朴素组 | 仅复用路由 TAIR |
| --- | ---: | ---: |
| 产物正确且正常结束 | 21/21 | 18/21 |
| 端到端总耗时（包含失败） | 207.79 秒 | 344.07 秒 |
| 已记录生成 token | 19670（完整） | 至少 11877（不完整） |
| 已记录逻辑输入 token | 223192（完整） | 至少 223958（不完整） |
| 已记录请求 | 82 | 53，另有 1 个未完成 assistant turn |
| 已记录分类控制记录 | 0 | 53，下界 |
| 工具错误 | 2 | 8 |
| 重复任务子集 | 4/4，35.48 秒 | 4/4，41.58 秒 |

失败：

- `unique_changed`：5.72 秒，正常结束且无工具错误，但错误复用旧实现，产物不满足新增约束。
- `nullable_base`：6.39 秒，同样错误复用、正常结束，产物未通过。
- `totals_base`：150.09 秒任务超时，已写入 SQL 通过产物检查，但第二次 assistant turn 未返回，不能算任务完成。超时调用未持久化完整 usage，所有 token、请求总量必须标为已知下界，不能据此计算 token 节省比例。

超时前服务端 running=1、waiting=0。按时间关联的引擎记录显示分类和 resume 均发生，见 [诊断记录](REUSE_ROUTING_TIMEOUT_AUDIT.json)；没有足够证据区分后续解码长尾、结构化输出处理或引擎状态停滞。客户端超时后未逐请求确认服务端取消完成，不能严格保证紧随任务在服务端完全没有重叠；此轮不用于精细性能归因，也不声称任何加速。

已完成请求的本地准备累计 6.89 秒、本地 tokenization 184 次，实际运行却更慢且质量下降。减少分类选项、tokenization 和生成 token 都不能代替端到端验收。误复用也不能靠工具执行成功发现：两项语义失败都正常结束。

`unique_changed` 的错误分类，最高两个候选 logprob 差为 1.25；更早试验的错误复用也存在更大分差。分差未经校准，不是语义正确概率，不能以一次阈值调整宣称修复。

结论：该路线只保留为明确标记的研究开关，默认关闭，未部署为用户配置。两轮实验均未达到同质量端到端加速。下一步应先定位续写长尾，并验证“检索内容作为草稿、由目标模型核验”的独立原型；这种方法本轮尚未实现，不预先承诺收益。
