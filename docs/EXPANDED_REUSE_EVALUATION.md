# 跨任务配对评估：功能正确性明显未达到原生基线

2026-09-20。本轮冻结后没有修改任务、提示、验收规则或被测 runtime，没有替换失败样本。
当前 TAIR 为包含显式内容门槛和差异提示的工作区版本；源码快照和哈希在实验目录。
完整模板关闭。实验目标是检验泛化与失败恢复，不继续针对已知失败调优。

## 方法与可比性

14 个新编写任务：JSONL 解码、JavaScript 字符串去重、SQLite 聚合、Python 区间合并，
每类包含首次实现、同需求新路径、改变自然语言约束；另有两个读取后修改 JSON 配置任务。
没有提供需要逐字复制的源码块，因此先前的显式代码块门槛不会替代语义判断。
独立 oracle 在模型工作区外，不注入推理上下文；先用参考实现和空输出验证 14/14 正例与反例。
任务及顺序在第一次模型调用前写入 manifest 并记录 SHA-256。属于新编写的有限任务族，
不是外部独立基准；参考实现验证只用于检查 oracle，不向模型提供。

两组均为 Pi 0.85.1，使用同一既有 yuesheng 6×RTX 5090 / DeepSeek 服务，串行运行。
朴素组使用 Pi 原生 provider 与普通 tools API，允许 parallel_tool_calls，提供同样的
read/edit/write/bash/grep/find/ls 七个原生工具；没有采用人为单步基线。
TAIR 对外只有 plan，内部调用相同原生工具。整体输出上限均 17408，TAIR 另有每子调用
2048 的限制；接口、提示、候选、缓存方式仍不同，不能将所有差异归到分类内核。
朴素组使用相同补丁服务的普通接口，未另起无补丁 vLLM。

同一任务对两组恢复相同初始文件及绝对工作路径；按固定随机种子交错组顺序，保留
每族 base→repeat→changed 顺序。TAIR 从用户现有 24 条码表的 SQLite 一致快照开始，
在隔离状态目录中持续学习，不清空；未修改用户日常码表或文件。每次新 Pi 会话，
状态库跨任务保留。共享 SSH 隧道准备不计时，Agent 时间包括启动、全部请求、工具、
恢复和最终回复；独立验收另记。每项超时 150 秒，无测试器自动重试。

## 失败类型与过程质量

- **八个任务没有执行任何工具便结束**：JSONL 三项、SQL 三项、区间合并 base、配置第一项。
  分类选了回复分支，部分回复说“准备写入/检查”甚至返回 schema 文本，但实际文件未完成。
- **一个误复用任务未恢复**：JavaScript changed 要求忽略大小写，却复用大小写敏感源码。
  Agent 的检查明确报错，最终却只回复准备修复，未再次执行。不能计为成功命中。
- **两项功能通过但自检没有收尾**：intervals_repeat 的测试漏导入；intervals_changed 的
  自写检查错误地要求合并相接零长度区间。Agent 最后表示将修复检查，却没有实际重跑。
  主表按预先冻结的独立功能验收口径仍计通过，不能据此说 Agent 工作流程已完整成功。
- 原生组也曾写错上述零长度检查，但实际修改检查并重新运行成功，费用已计入。

TAIR 有两个任务选择过内容复用，只有 unique_repeat 完整执行成功且通过独立验收；
unique_changed 写入了错误复用内容，随后计划检查失败。四个 repeat 任务中只有一个实际
成功复用；有些首次任务就没完成入表，不能再把所有重复尝试视作已有适用条目的选择实验。

现有“成功后入表”无法阻止所有错误：执行失败虽未入表，但已经写出的错误内容仍需要修复；
回复分支的错误终止也不受 schema 检查约束。此次不能仅靠改候选检索或码表容量解决。

## 后续优先级

先建立可靠的动作/结束判断、工具错误后的实际恢复，以及复用的约束验收；再讨论性能。
修复时应保留本轮作为开发集，并另冻结新任务检验，不能在这些用例调优后称为独立泛化提升。
下一轮还需码表关闭/清空隔离对照，才能区分历史候选干扰、规划提示和引擎分类的各自贡献。
