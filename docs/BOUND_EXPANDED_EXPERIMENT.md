# 扩大测试：绑定覆盖率与误命中

2026-09-19，Yuesheng 5090 现有服务。固定上一轮的候选编译器，不增加任务特定模板，扩展到 19 类任务，每类每组三次，共 171 次。16 类合成场景扩大值、路径、格式、约束与目录规模；3 类使用固定版本 CPython 的已有评估场景，未宣称为新收集的独立盲测。

## 测试设计

合成场景包括新值、改写表达、单字段、跨文件、指定文件范围、注释与空格、减半、否定翻倍、只改部分文件、混合操作、类型注解、其他字段名、类内变量、负数字面量、JSON、候选数量超限。CPython 为 v3.11.9、commit `de54cf5be371a6f5e2e9f208c38def5f81d3ef02` 的 diff 默认值、短别名及临时目录修复，原许可证保留在本地原始证据目录。

编译器仍仅识别顶层整数 workers/timeout 的翻倍；候选容量、解析失败保守返回空目录，三组均应用这一层回退，避免把编译器异常当成生成式失败。两个候选组在空目录时直接生成；目录非空时分别普通生成一个 ID或执行原有引擎 logits 分类。生成组生成最小替换片段，看到相同源码和候选信息。

独立预检枚举候选并执行验收，确定任务的潜在覆盖率；标准答案及验收程序不进入模型输入或绑定器。19 类中仅 6 类存在满足完整任务的候选，潜在覆盖率 **31.6%**。8 类为空目录，5 类有候选却没有正确答案，专门测试 NONE 拒识。每轮恢复源码并按重复序号打乱候选顺序，固定随机交错运行，不重跑替换失败。

三组均一次观察全部相关源码，仅执行一个编辑阶段，不是完整 Agent。计时包含候选构建、tokenization、模型及回退、执行和独立验收；初始文件恢复、预检与一次性标签 ID 准备单列。每次推理新缓存命名空间，无学习码表、无服务重启或新补丁。

## 错误机制

- 请求减半，候选只有翻倍；模型没有选择 NONE，实际把 workers 从 8 改为 16。
- 请求只修改多个文件的一个子集，模型选择了只覆盖其中一个文件的候选。
- 请求 workers 翻倍、timeout 减一，模型选择了两个字段都翻倍的候选。
- workers 带类型注解，编译器不支持它但仍提供 timeout 候选；模型选择了修改错误字段。

这些是完整任务语义错误，schema 合法、源码匹配及编译成功都无法排除。扩大候选覆盖范围可能改善命中率，但也不能代替拒识。

错误分类的候选 token 概率与第一、第二候选差距保存在派生指标中；存在最高 token 概率约 99.7%～99.8%、margin 6.5 的错误选择。token 概率不是操作正确率，简单提高置信度门槛无法挡住本轮所有错误。这里是错误诊断，没有在结果上调参再声称验证通过。

## 工程判断

当前不能将分类绑定默认用作开放任务的通用优化。可以保留空目录直接生成及严格确定的参数绑定；开放自然语言请求需要先证明完整任务可由候选表达，再考虑直接执行。普通短 ID 同样出现误命中，问题涉及有限候选选择与 NONE 拒识，不仅是 sampler bypass。

CPython 三类没有可用绑定，都直接生成。其正确性与耗时不能作为码表或分类命中的收益证据。旧的小样本提速结论仅对受支持任务成立，本轮没有证明总体等质量加速。
