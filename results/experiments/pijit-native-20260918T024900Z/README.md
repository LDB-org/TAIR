# 原生 Pi 与预设操作：同后端完整任务对照

2026-09-18。3 轮 × 2 个默认值任务 × 2 条路径，共 12 个正式任务。
另有一个原生 Pi 预检，保存在 preflight/，不计入正式比较。

## 比较对象与控制条件

- 原生组：Pi 0.85.1 自带的 openai-completions 流式 provider、read/edit 工具，
  调用 vLLM 标准 tools API。没有替换 provider 或原生工具实现。
- 预设组：pijit，开启 set_cli_default，保留 compact_edit 备选；六次均使用预设。
- 同一个 DeepSeek 服务、同一原始源码和用户任务，每对随机交错。温度 0，
  max_tokens 2048，thinking 关闭，原生 parallel_tool_calls=false。
  两边每次推理使用新 cache salt。原生控制/记录扩展仅设置请求参数并记账。
- 同一个**已打补丁 vLLM 服务**上的两条 API 路径；不是未打补丁与打补丁的部署 A/B。
- 两边都以完整 AST 和默认值/显式覆盖行为检查验收。
  原生工具不加验证钩子，只在最终完成时检查；预设保留额外的工具内验证和回滚。
- 汇总 wall_seconds 包含 Pi 启动、读文件、推理、编辑、最终回复、退出及相同的
  最终独立检查。预设额外的工具内检查也计入；fixture/tunnel 准备不计入。

## 正式结果

| 指标 | 原生 Pi | 预设 pijit |
| --- | ---: | ---: |
| 正确任务 | 6 | 6 |
| 推理请求 | 18 | 18 |
| 生成 tokens | 1375 | 258 |
| 分类控制记录 | 0 | 18 |
| 输入 tokens | 31035 | 33702 |
| 累计完整任务秒数 | 23.688 | 84.675 |
| 完整任务中位秒数 | 3.853 | 8.296 |

本批预设方案**没有比原生 Pi 快**。生成 tokens 减少约 81.2%，但输入增加
约 8.6%，两边都需要三次外层推理完成一个任务，没有减少请求次数。
18 条分类控制记录未混入实际生成 tokens。

原生输出包含原生工具帧、少量说明文字及绝对文件路径；预设组使用相对路径和
参数正文。因此输出减少属于整条调用路径的观测，不可全归因于预设模板。
归档项目路径较长，也会放大这项输出差异。两组的工具目录、提示、传输和
调用表达方式不同，不能当成只改变模板的消融。

共享服务有明显等待波动；现场快照为 4 个运行请求、2 个等待请求。
不把累计耗时或中位数比值解释成稳定变慢倍数。所有任务均保留，没有剔除长等待。
预设每个任务的 generation_preparation（包含 tokenizer 往返等）中位累计
为 1.603 秒，仍有客户端准备成本；这不是完整因果归因。
原生 API 缺少本次同口径分阶段引擎计时，不能精确拆解两边的排队与 GPU 时间。

## 证据与边界

原生 native-inference.jsonl 保留请求设置、HTTP 状态、终态和服务返回用量；
输入计数为 Pi 的 input + cacheRead + cacheWrite，未把 cached input 漏掉。
预设 metrics 同时保留外层与本地操作。全部 36 次正式推理用量完整，
无超时、错误或重试。预设的 18 次推理均复核分类旁路及 KV 续用事件。
原生预检成功且数据完整，单独保留，不加入正式组内累计。

backend-identity.json 保存模型下载 revision、配置/索引/引擎模块哈希；
未重新哈希完整权重。runtime.json 保存 Pi/Node 版本及原生工具实现哈希。
comparison/sources/ 保存实际执行的脚本副本与 manifest 哈希。
临时 auth/model profile 不进入归档。未修改模型、重启服务或覆盖旧实验。

结论只适用于这个很小的整数默认值 fixture。此前相对 C1–C3 的收益，
不能替代相对原生 Pi 的结果。若继续优化，优先测量并减少 tokenizer 准备、
Python bridge 启动和分类续写调度成本，而不是从 token 降幅推导加速。
