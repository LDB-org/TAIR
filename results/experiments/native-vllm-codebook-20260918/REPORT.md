# 普通 vLLM 工具调用与 TAIR 对照

## 结论

同一 yuesheng 6×RTX 5090、同一 DeepSeek 服务，63 次编辑均通过行为检查。
本组优化后 TAIR 的总耗时相对普通工具调用下降 69.1%，耗时比为 3.24×。
九次码表命中任务平均耗时从普通工具调用的 1.015 秒降至 0.187 秒，下降 81.6%。
这是小型编辑内部闭环的测量，不能解释成整个 Agent 或任意 vLLM 工作负载加速 3.24×。

## 对照含义

- **普通 vLLM**：`/v1/chat/completions`，普通 `edit` function tool，`tool_choice=auto`，
  模型输出 `path/oldText/newText`，要求选择最小充分替换。无 TAIR 分类标志、
  无额外 `structured_outputs`。原始回复确认真实 tool call，reasoning tokens 为零。
- **TAIR 紧凑生成**：引擎选择操作，再生成紧凑参数；禁用码表。
- **TAIR 优化码表**：相同紧凑路径，首次生成入表，后续用分类及显式绑定检查复用。

三者使用同一个已打补丁的服务。普通请求没有走直接分类 hook，但这里没有启动
单独未打补丁的 vLLM 实例。因此这是普通接口路径与 TAIR 路径的比较，不是两个
vLLM 二进制版本的严格 A/B。也没有运行完整 Pi；原生文本替换在本 harness 内执行。

## 方法

七种情境：首次修改默认值、重复任务、新参数值、同义表述、源码追加注释、添加别名、
重复添加别名。每种三轮独立重复，每轮三条路径随机交错，共 63 次编辑。
每个 arm/repeat 初始码表为空；各任务恢复指定原始源码，保留该轮码表。
源码恢复、读完源码后的任务文本与行为检查在三个 arm 之间一致。

所有推理 temperature=0、max_tokens=2048、关闭 thinking、使用独立 cache salt。
无重试，不启用 tokenizer 标签缓存、精确重放或预设操作路径。
普通编辑先检查目标路径和唯一替换位置，再编译；三个 arm 共享同一备份、原子写入、
验证和失败回滚函数。每次行为检查验证默认参数、显式参数覆盖、action 数量；
别名任务还验证短选项。默认码表中原源码和修改后源码均可登记。

完整编辑 wall time 包括客户端准备、HTTP、推理、备份、写入和行为检查，
不含外层 Agent 的规划、读文件和最终回复。共享服务、短合成任务、三轮重复，
没有据此估计生产吞吐或尾延迟。

## 结果

| 指标 | 普通 vLLM | TAIR 紧凑生成 | TAIR 优化码表 |
|---|---:|---:|---:|
| 行为检查通过 | 21/21 | 21/21 | 21/21 |
| 码表复用 | 0 | 0 | 9 |
| 推理请求 | 21 | 21 | 21 |
| 生成 tokens | 2,172 | 210 | 120 |
| 分类控制记录 | 0 | 21 | 21 |
| 输入 tokens | 8,106 | 10,146 | 6,897 |
| 总编辑耗时 | 21.563 s | 8.699 s | 6.655 s |
| 编辑耗时中位数 | 1.015 s | 0.414 s | 0.411 s |
| 九个可复用情境的平均耗时 | 1.015 s | 0.414 s | 0.187 s |

普通列的生成量取 API `completion_tokens`，包含工具调用序列化；TAIR 列只计生成
参数，分类控制记录另列。计入控制后，TAIR 优化输出单位为 141，相对 2,172 减少
93.5%。输入计算不能忽略：紧凑生成的输入量在本组反而高于普通调用。

普通路径实际多数生成完整 `add_argument(...)` 语句的 old/new 配对（尽管提示要求
最小充分替换），例如首次任务生成 102 tokens；紧凑路径只生成 10 个参数 tokens。
这反映本提示和模型的实际行为，不是声称普通工具调用必须生成这么长。

收益可拆分为：紧凑生成相对普通工具调用总耗时下降 59.7%；优化码表再相对紧凑
生成下降 23.5%。不能把全部收益归因于分类或码表。因为多数任务仍需生成，
整个任务集的中位数只小幅变化；命中子集的收益更大。
