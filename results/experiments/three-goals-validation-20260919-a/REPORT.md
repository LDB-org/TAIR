# 正确性、原生多工具基线与真实仓库码表实验

本轮围绕三个问题：正确性是否达到原生工具调用水平；开启原生多工具输出后仍有多少优势；学习到的编辑能否在真实仓库命中并节约完整任务时间。

## 方法和边界

运行使用已有 Yuesheng 六张 RTX 5090 服务，未安装新补丁或重启。服务容器仍为 `vllm-deepseek-v4-sm120-situ`，启动时间为 `2026-09-18T05:44:43.699377485Z`。客户端使用隔离 Python 3.11 和 Pi 0.85.1。

原生组使用同一服务器的普通 tools API。早期 pilot/仓库 A 每次请求使用新 cache salt；后续强基线改为配置内部可复用、配置之间隔离，以下分阶段报告。`native_single` 设置 `parallel_tool_calls=false`，`native_multi` 设置为 `true`；实际请求参数与每个回复中的工具数量独立核验。这不是独立部署的未打补丁 vLLM 对照，也不把允许多工具输出等同于每题都实际输出多个工具。

完整任务计时包括规划、模型请求、工具执行、测试、恢复、最终回复和外部行为验收。初始项目恢复与后验审计单列。生成 token、分类控制记录、输入 token 和未知用量分别记录。超时请求的已知 token 只能作为下界。

每个配置使用自己的空状态目录。早期和十类扩展对照的配置使用不同项目路径；后续 CSV 重复与仓库 B 共用同一任务绝对路径，缓存命名空间由独立状态目录区分。暖轮恢复相同绝对路径的原始源文件，保留该配置学习到的码表，启动新会话。没有预置正确编辑；第三轮的受支持 CLI 任务更换参数值或别名，以区分精确重复和模板绑定复用。没有用重新运行的成功样本覆盖失败。

真实仓库选取 CPython v3.11.9、commit `de54cf5be371a6f5e2e9f208c38def5f81d3ef02` 的 `Tools/scripts`，原许可证保留。任务包括 `diff.py` 默认值、长短别名、显式 UTF-8 读取和 `update_file.py` 的绝对路径临时目录问题。它们是固定上游代码上的有限修改任务，不代表 CPython 全量测试或一般软件工程基准。任务需要临时文件验收；Agent 工具不构成操作系统级沙箱。

外部验收先确认原始代码失败、参考修改通过；参考修改不提供给 Agent。检查真实 CLI 输出、原选项兼容性、临时文件位置和字节内容，保留其他源文件。CLI AST 比较允许保留原字段名的显式 `dest='lines'`，不把等价的安全别名写法误判为错误。

## 已否决的正确性方案

三个独立 pilot 目录保留提示与校验门槛的全过程：

- A：共享完成要求提示；三个组均未正确处理 CSV 的 quoted embedded newline。
- B：更明确地要求实际断言并放在系统提示末尾；原生多工具组通过 CSV，两个 TAIR 组仍失败。
- C：编辑后强制生成带断言的 Python 校验脚本，成功执行前不交付最终答案。两个 TAIR CSV 任务均在 180 秒超时；模型生成的校验脚本也会出错，形成反复校验和恢复。

因此，不能声称“加一次自检就恢复了正确率”。失败门槛的实现和请求轨迹留在 pilot 快照中，后续正式比较关闭此门槛。完成要求提示也采用显式 opt-in，不凭开发样本直接改变默认行为。

## 已修复的确定性缺陷

原紧凑 `arg` 操作在参数列表最前面插入别名。对 `add_argument('-l', '--lines', ...)` 插入 `--context-lines` 会使 argparse 默认字段从 `lines` 变为 `context_lines`；语法和编译都通过，但调用方访问 `options.lines` 会失败。

新增保守检查：如果前插会改变或无法确定隐式 destination，则不走本地别名路由，紧凑操作也在写入前拒绝；普通编辑仍可追加别名或显式保留 destination。该规则也覆盖只有短选项时前插另一短选项改变字段名的问题。回归测试检查新旧 CLI 选项实际解析出的 Namespace，未将任务答案写入运行时。

## 新组合与强基线

强制校验门槛从当前实现移除，源码留在 pilot C 快照。完成要求提示仍可显式启用，但以下新对照全部关闭。

| 配置 | 外层规划 | 多工具输出 | 前缀缓存隔离 | 编辑码表 |
|---|---|---|---|---|
| native_single | Pi 原生 tools API | 关闭 | 每个配置/任务固定 salt | 无 |
| native_multi | Pi 原生 tools API | 开启 | 每个配置/任务固定 salt | 无 |
| tair | 原分类与批量计划路径 | 自定义 execute_plan | 每次请求新 salt | 原模型筛选 |
| hybrid_no_book | 原生工具调用消息结构 | 开启 | 每个 workspace 固定 salt | 关闭 |
| hybrid | 原生工具调用消息结构 | 开启 | 每个 workspace 固定 salt | 唯一明确绑定本地复用，其余保留原筛选 |

原生 single/multi 只有 `parallel_tool_calls` 不同。hybrid 开关码表的两组也只有 `PIJIT_DISABLE_CODEBOOK` 不同；配置回归测试验证此条件。所有组每次回复上限为 2048 token、每题上限 120 秒。服务现场确认有 `--enable-prefix-caching`；新原生与混合路径允许配置内部冷暖轮复用，组间仍隔离。接口未返回 cached-token 明细，不宣称量化了前缀缓存的单独收益。

hybrid 保留本地明确请求路由与 compact_edit，开放任务使用普通生成式规划。其批量工具执行仍顺序执行、遇错停止，输出多个 tool call 的能力来自原生 vLLM。外层不再把工具结果压成用户文本，也不再强制所有决策进入 reply/execute_plan 二选一。

新增 `PIJIT_BOUND_REUSE=1` 只有在源码匹配、绑定可识别、候选唯一且编辑字段完全匹配时跳过模型筛选。冷轮仍需生成并入表，暖轮可绑定新的值；语法、编译及配置的项目校验照常执行。不满足条件就保留模型筛选或生成回退。别名自动绑定还要求可识别的 argparse 接收者。这是本地类型约束下的动态模板复用，不是新训练的分类头，也不是任意程序内容的语义复用。只有 compact_edit 支持且验证通过的生成操作进入此码表；普通 edit/write 的任意生成结果仍不会自动学习。

compact_edit 给模型看的结果不再混入缓存命中和 token 统计；这些仍保存在工具 metadata、trace 与状态栏。开关码表后，相同编辑不会仅因计量信息不同就改变后续规划提示。

新组合 pilot 在 CSV、修复并新增测试两题各跑原生多工具/混合一遍，4/4 通过，包括新增测试的变异审计。CSV 原生 11.054 秒、混合 11.029 秒；新增测试原生 11.203 秒、混合 16.695 秒。这只是进入扩展对照的门槛，不是提速或泛化结论。

## 结果

### 十类任务，四组各一次

全部通过任务完成、独立行为验收和测试完整性检查；新增测试还通过负数求和与输入修改的变异审计。

| 配置 | 通过 | 完整总耗时（秒） | 推理 API 请求 | 多工具回复 | 码表命中 |
|---|---:|---:|---:|---:|---:|
| 原生单工具 | 10/10 | 120.474 | 79 | 0 | 0 |
| 原生多工具 | 10/10 | 122.133 | 64 | 13 | 0 |
| 原分类批量路径 | 10/10 | 89.567 | 34 | 20 | 0 |
| 混合原生规划路径 | 10/10 | 114.403 | 54 | 12 | 0 |

原生多工具实际产生了 13 次多工具回复，请求数减少，但这一轮并未比原生单工具更快。混合组比原生多工具少 6.33% 时间，比本轮更快的原生单工具少 5.04%。旧批量路径仍然最快。这里没有任何码表命中，不能用这些差值证明码表提速。每类只跑一次，路径尚未统一，不把这张表当成稳定性能排序。

### CSV 三次重复：检查单次通过是否稳定

扩展对照中旧分类路径也通过 CSV，因此追加三次重复，没有替换原失败记录。每次重复三组共用同一项目路径，配置缓存独立。

| 配置 | 独立验收通过 | 完整总耗时（秒） |
|---|---:|---:|
| 原生多工具 | 1/3 | 39.524 |
| 原分类批量路径 | 1/3 | 23.487 |
| 混合路径 | 3/3 | 29.712 |

四个失败都把 `text.splitlines()` 交给 `csv.reader`，丢失带引号字段里的换行。没有超时或用量缺失。混合路径在这组小样本中更稳，但不能把三次通过升级为通用正确性保证；切换规划协议、工具目录及消息表达是组合变化，尚未逐项隔离。

### 真实仓库 A：提示强化没有解决完成问题

五类任务、三组、每组冷暖/第三轮各一次，共 45 次。

| 配置 | 正常完成且验收通过 | 产物验收通过 | 总秒数 | 超时 | 码表命中 |
|---|---:|---:|---:|---:|---:|
| 原生多工具 | 9/15 | 15/15 | 736.640 | 4 | 0 |
| 分类批量、关闭码表 | 12/15 | 14/15 | 662.533 | 2 | 0 |
| 分类批量、开启码表 | 12/15 | 15/15 | 545.368 | 3 | 4 |

此阶段启用了额外完成要求提示，尚未允许原生前缀复用。原生的若干代码产物已正确，却在后续验证中超时或达到 2048 token 输出上限；不能描述成代码全部失败。TAIR 关闭码表的一个长别名任务没有完成要求。

码表开关的完整任务总时间相差 117.165 秒，但编辑内部只相差约 1.212 秒，剩余主要是不同规划/验证轨迹。不能把这 117 秒归因于码表。这批失败促使后续关闭提示强化并更严格控制路径和配置。

### 真实仓库 B：码表开关的直接对照

两组都用原生规划和同一项目路径，缓存命名空间分离；compact_edit 对相同编辑返回的文本不含码表开关差异。五类任务各跑冷轮；默认值与短别名额外跑精确重复和新参数绑定。每组九次，共 18 次，全部正常完成、验收通过，无超时，用量完整。

| 指标 | 关闭码表 | 开启码表 |
|---|---:|---:|
| 九个完整任务总秒数 | 146.558 | 150.220 |
| 全部推理 API 请求 | 50 | 52 |
| 其中外层规划请求 | 44 | 50 |
| 其中编辑请求 | 6 | 2 |
| 暖轮命中 | 0 | 4 |
| 四个暖编辑内部总秒数 | 4.966 | 0.039 |
| 四个暖编辑推理请求 | 4 | 0 |
| 四个暖任务完整总秒数 | 51.573 | 53.004 |
| 四个暖任务外层规划请求 | 17 | 21 |

四次命中包括目标参数由 `5` 换成 `7`、目标别名由 `-C` 换成 `-N` 的新绑定；每轮起点均恢复为上游原始源码，并非跨任意项目泛化。冷轮确实先生成并入表；暖命中后编辑侧输入 token、生成 token、分类控制记录均为零。

编辑内部共节约 4.927 秒；该时间不含 Python 进程启动、外层规划和任务测试。完整暖任务反而多 1.431 秒（2.77%），全部九题多 3.662 秒（2.50%）。其他环节的时间与请求变化吞掉了节省。这只能证明受支持任务的内部复用有效，**本轮没有证明完整 Agent 的净提速**，也不能凭这组小样本断言码表必然拖慢。

## 实现与验证状态

- 保留 opt-in 原生规划、明确绑定复用、批量模式内本地路由；标准编辑结果保留 diff 与验证范围，计量留在 metadata/trace。
- 修复会改变 argparse destination 的前插别名。运行结束后额外补上 `dest=None` 仍采用隐式 destination 的边界；该分支由本地回归测试覆盖，以上 GPU 计时来自修补前冻结快照，测量任务未走这个分支。
- 315 项本地测试通过。历史及本轮冻结文件执行 SHA-256 校验；没有安装服务补丁或重启，末次 `/health` 返回 200，容器启动时间及镜像标识未变。
- 本轮共 134 次完整 Agent 尝试，含否决的原型及全部失败。不同配置/阶段不合并成一个项目成功率。

数值与阶段摘要见 [THREE_GOALS_RESULTS.json](THREE_GOALS_RESULTS.json)。原始日志、源码快照和校验清单保存在 `results/experiments/three-goals-*`；含上游 CPython 评估素材的 repository 目录按仓库要求仅本地保存，Git 忽略，公开摘要不包含其源文件。

## 复现

先使用独立 Python 环境安装项目测试依赖，安装 Pi 0.85.1，并将已有兼容服务通过本地 SSH 隧道暴露；本实验不安装 vLLM 补丁。`REVISION` 必须是核验过的当前 tokenizer revision，不能照搬到别的模型。

```sh
python benchmarks/benchmark_three_goals.py --url "$URL" --out /path/to/new-expanded-results \
  --tokenizer-revision "$REVISION" --rounds 1 \
  --arms native_single native_multi tair hybrid

python benchmarks/benchmark_three_goals.py --url "$URL" --out /path/to/new-csv-results \
  --tokenizer-revision "$REVISION" --cases quoted_csv --rounds 1 --repeats 3 \
  --arms native_multi tair hybrid

python benchmarks/benchmark_three_goals.py --url "$URL" --out /path/to/new-repository-results \
  --tokenizer-revision "$REVISION" --repository /path/to/cpython-v3.11.9 --rounds 3 \
  --warm-cases cpython_diff_default cpython_diff_short_alias --arms hybrid_no_book hybrid
```

CPython 工作副本须位于上面的固定 commit，并含 LICENSE、README.rst 与 Tools/scripts。当前 runner 已统一配置间的任务绝对路径；精确复现早期十类对照需使用其归档源码。各目录保存对应的运行、后验审计、分析脚本及 SHA256SUMS。脚本需要只读原始日志，分析新副本；不要重写冻结目录。
