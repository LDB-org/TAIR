# 预设码表：真实 pijit 循环对照

2026-09-18。首个预设操作为 `argparse_int_default/v1`，由外层模型生成
`path / option / expected_default / value`，本地检查并替换默认值，不调用内层模型。
实验入口 `benchmarks/compare_pijit_presets.py`，固定种子 20260919，2 轮，
每轮分别把默认值 4→6→8，三条路径交错执行，共 12 个完整任务。

每条路径都是实际 Pi 0.85.1 的 read → 编辑工具 → 最终回复循环。
预设组仍保留 compact_edit 作为备选，实际四次都选择了 set_cli_default。
基线为紧凑生成（C1–C3），并不是原生 Pi 或未打补丁 vLLM。
C4 组保留原门控和准入策略；三组的外层工具目录/提示词不同。

每对任务输入源码一致、项目与状态目录独立，每轮码表从空开始。
每次编辑在计时区间内执行相同的任务 oracle：先验证完整 AST 符合预期，
再检查 argparse 默认值及显式覆盖。独立的末尾复核另行计时，不包含在任务 wall 中。
wall 包含 Pi 进程启动、读文件、全部外层/内层推理、编辑验证、最终回复与退出；
不含准备 fixture 和 SSH 隧道。所有请求、恢复、失败或超时均保留；本轮无失败或超时。

## 动态码表为何仍未产生收益

真实 Agent 把 compact_edit 的任务写成“默认值从 4 改到 6”一类措辞，
同时包含旧值与新值。当前 integer_binding 要求恰好一个整数，因此四次
编辑均未入库，也没有缓存分类或命中。预设接口将旧值与新值分成类型化字段，
无需再次从自然语言推断绑定。这与先前手写单整数 task 的 C4 实验不同。

## 实现与证据边界

预设只接受目标唯一、显式 type=int、已有字面量整数默认值及简单 argparse
变量绑定；旧默认值不匹配即拒绝。它保留源码冲突检查、备份、原子替换及项目
检查失败回滚。它不是任意 Python 语义证明，也不保证外层模型符合用户意图。
实际客户端默认仍只有结构与编译检查；实验配置的任务 oracle 更强。

44 次推理均匹配到 V2 分类旁路和 KV 续用事件，详见 engine-events.jsonl
与 engine-checks.json。模型下载 revision、配置/索引/引擎模块哈希见
backend-identity.json，未重新哈希完整权重。服务未重启，门控未降低。

comparison/ 保存逐任务事件、stderr、源码前后快照、metrics、summary
及本次执行的源码副本和哈希。生成的 Pi auth/model 运行时 profile 已移到
私有临时目录，不进入证据归档；项目 metrics、备份与所有结果保留。
实验结束后，维护版 runner 改为从一开始将 profile 放在临时目录，
该归档的 runner 源码副本仍保留本轮实际执行版本，未重写历史证据。
