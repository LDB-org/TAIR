# Pi 引擎协议：原始参数正文与并发实验

## 改动

新增可选 `engine_raw` 模式，保留旧 `engine` 为默认值。
旧协议只在 Schema 最后一个字段是必填字符串时使用原始正文；当前新模式额外允许最后一个必填字段为
`command` 字符串时，先生成其他字段的固定位置 tuple，再生成命令正文。
例如 bash 从 `B\n["转义后的命令",30]` 改为 `B\n[30]\n` 后接原始命令。
不改变工具名称、能力或最终参数对象，不添加原生回退。
所有可选字段仍有固定位置并验证类型；缺失项使用 null。字符串内换行不会被当成新的工具调用。

初版曾对所有最后一个必填字符串采用此处理，导致 read/find/grep 的短字段也成为无边界正文。
完整 Pi 会话发现模型在 path 中串入后续工具帧；这些字节被当成一个路径值，没有被解释成多个可执行调用。
两条初版会话被主动终止，保留失败证据，没有算作完成任务。
当前修订版只额外放开 command，read/find/grep 仍用原有 tuple 边界。
edit 的最后一个必填字段是嵌套 edits 数组，本轮未优化其编码。
新增测试覆盖可选参数、Unicode、多行命令、截断拒绝以及嵌套数组布局保持不变。

## 测量设计

`benchmarks/benchmark_pi_concurrency.py` 在推理主机直接访问现有 vLLM，避免把逐请求 SSH 启动差异当成 GPU 收益。
真实 Pi 的全部 8 个内置工具及 reply_user Schema 每次都提供给模型。
固定 4 类调用及精确目标参数：bash 多行命令、edit 嵌套替换、write Python 正文、reply_user 中文回复。
三个协议模式 native/engine/engine_raw × 并发 1/2/4 × 每类两次，共 72 个请求。
配置顺序及配置内任务顺序使用固定种子打乱；每个请求独立 cache salt，temperature=0、thinking=false。
测试只生成调用，不执行这些命令；任务彼此独立，具备并发条件。

正确性使用完整调用对象的精确比较，不忽略开头空行或末尾换行，不用 trim 提高成绩。
所有失败保留 usage 与时间，分别报告总请求吞吐和正确调用吞吐。
单轮调用吞吐不是完整 Agent 任务吞吐，也不是同一 Agent 依赖步骤可以并行的证据。

现场容器 `vllm-deepseek-v4-sm120-situ`：`--max-num-seqs 4`、`--max-num-batched-tokens 1024`、priority 调度。
镜像 `sha256:c0dec7f60c449fc4089134dcbc2b80462e9d39622fa33dba83dfb0b1d90987dc`。
本轮不改这些参数、不重启服务、不修改模型权重。
现场源码的 async scheduler 会标记 pending structured output，engine core 存在等待 token 后更新 grammar bitmask 的路径。
只确认这条依赖路径存在，没有测得它占用的时间，也不能将全部延迟归因于它。

## 边界

这是共享服务上的小样本筛查；并发会同时影响排队、批处理、每 token 延迟和输出结果，
不同配置并非同时在完全相同外部负载下运行，不能由一次矩阵宣称稳定吞吐倍数。
原始字符串仍可能被模型额外添加空行；结构合法不能保证精确复制。
该模式保留为可选实验，不因局部速度改善直接成为默认值。

## 修订版：两个真实 Pi 会话并发

收窄为 command 优化后，在两个独立目录并发运行完整工具覆盖任务，使用真实 Pi loop、工具和错误回传。
结果目录：`results/experiments/pi-parallel-agents-20260918-b/`。

| 指标 | Agent 0 | Agent 1 |
|---|---:|---:|
| 最终独立验收 | 通过 | 失败 |
| 实际模型请求数 | 9 | 20 |
| 输出 tokens | 597 | 180 |
| 总 tokens | 22403 | 53860 |
| 累计生成时间 | 12.714 s | 4.086 s |
| 累计排队时间 | 58.229 s | 87.190 s |

Agent 0 完成所有工具调用，模型的 5 项 unittest 与额外 6 项独立行为检查通过，耗时 85.60 秒。
Agent 1 连续将 `ls` 当成路径交给 read，20 次返回合法但错误的调用，随后本地轮数限制停止。
日志中第 21 条是本地限制事件，没有发起模型请求，不把它计入实际请求数。
两条会话整批 122.64 秒，只成功 1/2；总 29 请求、777 输出 tokens、76263 总 tokens，失败成本全部保留。

不能只取成功会话宣称整体加速，也不能据此断定并发导致模型选错工具；当前缺少同条件重复和消融。
本轮证明了命令正文存在可测的性能优化空间，并实现了有界并发测试，尚未得到可推荐的稳定并发 Agent 配置。
工具选择、错误后的重复调用与原始回复的精确性需要先改进，不能单靠增加并发解决。

129 项 pytest、原始 raw SHA256 与 69 项 published claims 校验通过。
源码和逐行证据分别冻结在各实验目录；运行后的批处理脚本另补充了“任一子进程失败则非零退出”，
实际实验的子进程退出码以 batch.json 为准。默认 engine 模式、共享服务配置均未改变。
